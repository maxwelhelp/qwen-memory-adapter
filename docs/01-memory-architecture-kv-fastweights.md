# Архитектура обучаемой памяти для LLM (KV-память, fast weights, тернарная/LoRA-память)

Свод идей из диалога про то, как прикрутить к замороженной LLM внешний обучаемый модуль памяти: от идеи "мини-внимание подсказывает агенту" до рабочей схемы "детектор + проектор + LoRA-память", выровненной с пространством основной модели.

---

## 1. Исходные компоненты идеи

1. **"Подсказывающее" внимание (адаптивные хинты агенту)** — отдельная маленькая голова/подсеть, которая на основе состояния основного внимания + памяти генерирует не токены ответа, а мета-инструкцию для следующего шага. Технически близко к gating-сети в MoE, только выход — не "какой эксперт", а "какая подсказка". Главный риск не архитектурный, а обучающий: нужен сигнал "что такое хорошая подсказка" — либо RL с reward-моделью, либо дистилляция с более сильной модели.
2. **Детектор раздражения/ошибок** ("если через ~20 попыток получилось — сохранить как скилл") — не attention-механизм, а классификатор на скрытых состояниях (небольшая attention-голова или линейный пробинг). Сохранение "как скилл" — это episodic/skill memory, уже реализовано в агентных системах: **Voyager**, **Generative Agents**, memory-stream подходы. Скилл там — переиспользуемый артефакт (промпт/код/паттерн), достаётся через retrieval, а не встраивается в веса.
3. **JSON-лог об ошибках/успехах/исправлениях** — просто структурированный лог. Отдельная (можно маленькая) модель-классификатор поверх диалога выдаёт структурированную сводку на каждом шаге или в конце сессии. Самая дешёвая часть.

### Ключевое архитектурное решение
Записывать в веса на лету (test-time weight update, как в **Titans**) — дорого и рискованно (catastrophic forgetting, дрейф). Писать во внешнюю память (вектор/граф БД) и доставать через RAG — дёшево и предсказуемо.

## 2. Стоимость по инференсу — три сценария

| Что добавляешь | Накладные расходы |
|---|---|
| Маленькие доп. attention-головы, параллельно основному forward pass | единицы % до ~10–15%, если головы реально маленькие (низкая размерность, мало слоёв) |
| Реальное обучение весов на лету (Titans: surprise-based update на каждом токене) | дорого: доп. градиентный шаг может добавить 20–50%+ в зависимости от частоты/цены update rule |
| Запись во внешнюю память (не в веса) | почти бесплатно для модели; дорого только по латентности retrieval (векторный поиск), можно делать асинхронно/параллельно |

## 3. Рекомендованное разделение на два слоя

- **Внутри модели** — только лёгкие головы для генерации подсказок / классификации раздражения на уровне текущего диалога (живёт только в контексте сессии, не персистентно).
- **Снаружи модели** — персистентная память (skill library, история ошибок/исправлений) как отдельная система с retrieval, куда пишет "судья"-классификатор после сессии или каждые N шагов, а не сама трансформерная сеть в реальном времени.

Снижает риск catastrophic forgetting, упрощает отладку (видно, что записалось в память, в отличие от неявных изменений весов).

## 4. Веса как key-value память — это буквально так

**Geva et al., "Transformer Feed-Forward Layers Are Key-Value Memories"** — FFN-слой трансформера математически есть key-value память: первая матрица — ключи, вторая — значения, активация между ними — "насколько текущий вектор похож на записанный ключ".

### Fast weights / быстрое переписывание весов на лету
- **Шмидхубер (90-е), "fast weight programmers"**: одна сеть генерирует не выход, а *изменения весов* другой сети в реальном времени — "запись" информации прямо в матрицу как в память.
- **Titans** — современный потомок этой идеи.
- Linear attention можно переформулировать как rank-1 обновление матрицы памяти на каждом токене — внимание и "запись в веса" в некоторых формулировках одно и то же с разных сторон.

### Тернарные веса
Направление обозначено в диалоге как **"Bonsai/BitNet"** — два упомянутых имени тернарных/квантованных архитектур. Подробно разобран именно **BitNet b1.58** (2024) — реальная опубликованная архитектура, веса буквально {-1, 0, 1}. Обучение через straight-through estimator (STE) для дискретизации; инференс дешевле в разы (матричное умножение → сложение/вычитание/зануление). Комбинация "тернарные веса + fast weight память" публично особо не сведена вместе — щель для оригинальной идеи.

### Hypernetwork
Одна сеть генерирует веса (или дельту весов) другой сети из вектора-контекста. Пример: генерация LoRA-дельты "на лету" из контекста разговора вместо статичного дообучения — небольшая сеть-проектор (эмбеддинг → низкоранговая дельта весов), реализуемо уже сегодня из существующих кирпичей.

## 5. Где щель для прорыва

Три отдельные, но совместимые идеи:
1. Внешняя векторная память (retrieval) — дёшево, но неглубоко интегрирована с весами.
2. Fast weights / hypernetwork запись прямо в веса — глубоко интегрировано, но дорого и рискованно (забывание).
3. Тернарные/квантованные веса — дёшево по инференсу, пока не связано с 1 и 2.

**Нетронутая комбинация**: тернарная/дискретная fast-weight память, адресуемая ключом, где "запись" — не градиентный шаг, а дискретная операция (+1/-1/0 в ячейку по хэшу ключа), как ассоциативная память типа Hopfield-сети, но тернарная. Даёт: дешёвую запись, дешёвое хранение (1.58 бита/параметр), потенциальную устойчивость к забыванию (дискретные операции легче версионировать, чем непрерывные градиенты).

## 6. Детекция vs запись — два разных сигнала

- **"Модель не уверена / не знает"** — детекция, вытаскивается из внутренних представлений (энтропия распределения на выходе, разброс в attention, норма скрытого состояния). Отдельная маленькая головка (можно тернарная) смотрит на скрытые состояния и классифицирует: уверенно / неуверенно / вероятно ошибка.
- **Запись во внешнюю память по этому сигналу** — не градиентная, а дискретная адресуемая операция: ключ (эмбеддинг ситуации/факта) → хэш → найти/создать ячейку → записать +1/0/-1.

Мини-сеть не "обучает" основную модель в смысле градиентов — она выступает **контроллером записи** во внешнюю структуру. Это принципиально более безопасный механизм, чем прямое обновление весов трансформера.

## 7. Общий латент: развилка А/Б

- **Вариант А — общее пространство.** Мини-сеть работает прямо со скрытыми состояниями основной модели (тот же residual stream), без промежуточного перевода. Плюс: ничего переводить не надо. Минус: если основную модель дообучают, геометрия пространства "плывёт", память протухает.
- **Вариант Б — своё пространство + проекция.** Мини-сеть со своим эмбеддингом + обучаемый линейный/нелинейный проектор в обе стороны. Плюс: устойчивее к изменению основной модели, версионируется отдельно. Минус: лишний слой, который тоже надо обучать.

Для адаптера к существующей сети — рекомендация **вариант Б** (не лезешь внутрь исходной модели, подключаешься сбоку).

## 8. Как токены "попадают в веса" — механика

Обычное обучение: токен → эмбеддинг → градиент по loss → маленькое изменение *всех* весов сети (дорого, размыто).

Предлагаемый механизм: токен/факт → эмбеддинг → **хэш этого эмбеддинга указывает на конкретную ячейку** в отдельной небольшой матрице памяти → в ячейку пишется дискретное значение. Не градиентный спуск по всей сети, а адресация как в хэш-таблице, но "адрес" вычисляется нейросетью. Ближе всего к **Neural Turing Machine / Differentiable Neural Computer** (внешняя память с адресацией по контенту, обучаемая через backprop) — только с дискретным (тернарным) вариантом вместо непрерывного.

## 9. RAG-пространство vs "пространство весов" сети

- **RAG-пространство** — статичные векторы, посчитанные один раз энкодером. Поиск = косинусное сходство. Никакого "мышления" при поиске, чистая метрика расстояния.
- **"Пространство весов"** (Geva et al. про FFN) — ключи это *обучаемые параметры самой модели*, меняются в процессе обучения; "поиск" — softmax-активация через нелинейность, часть единого дифференцируемого вычисления, а не отдельный шаг "найти-и-подставить".

Тернарная память — гибрид: адресация как в RAG (по ключу/хэшу), но интеграция как в весах (напрямую участвует в forward pass).

## 10. Итоговая архитектура (дискретная тернарная версия)

```
[Основная LLM, веса заморожены]
        │  скрытое состояние h_t на каждом шаге
        ▼
[Детектор (мини-attention, можно тернарный)]
   — оценивает: уверенность / ошибка / успех / "запомни это"
        │
        ├── если "не пиши" → продолжаем как обычно
        │
        └── если "пиши" →
                │
                ▼
        [Проектор h_t → k_t]  (эмбеддинг ключа в своём пространстве)
                │
                ▼
        [Хэш k_t → адрес ячейки в тернарной памяти M]
                │
                ▼
        [Запись: M[адрес] = ±1/0]  (не градиент, дискретная операция)

При следующей генерации:
[Основная LLM] → h_t → [Проектор → k_t] → [Хэш → чтение из M] →
    [Проектор обратно в latent основной модели] →
    добавляется в residual stream / подмешивается в attention
```

Обучается так: детектор и оба проектора — через backprop как обычно (замороженная основная модель + маленький адаптер сверху, LoRA-подобная схема). Матрица памяти M — не через backprop, а через явное правило записи (Hebbian-подобное: "усиливай связь, если сигнал совпал с ожиданием, ослабляй если разошёлся" — по духу как в Hopfield-сетях).

**Что реально ново:** детектор + проектор + LoRA-адаптер — стандартные проверенные кирпичи. Тернарная адресуемая ассоциативная память с хэш-роутингом, подключённая как внешний модуль к замороженной LLM через обучаемый проектор, — комбинация без опубликованных аналогов в такой сборке. Главный открытый вопрос — правило записи (backprop через дискретные операции не работает напрямую).

## 11. Упрощённая (реализуемая) версия: LoRA-память вместо дискретного хэша

```
h_t (скрытое состояние основной сети)
    │
    ▼
[Проекция P: h_t → e_t]   (в пространство памяти)
    │
    ▼
[LoRA-адаптер поверх памяти]  ← сюда идёт градиент
    │
    ▼
запись/обновление вектора памяти
```

"Запись" — обычный градиентный шаг, но **ограниченный низкоранговой матрицей (LoRA)**, а не полным весом. Резко снижает и стоимость, и риск catastrophic forgetting.

### Родственные направления
- **Test-Time Training (TTT-layers, 2024)** — слой, который во время инференса делает мини-градиентный шаг по своим внутренним весам на основе текущего контекста, заменяет/дополняет attention. Встроено внутрь архитектуры, не адаптер сбоку, но принцип "запись = градиентный шаг по маленькой матрице" тот же.
- **Transformer² (Sakana AI, 2025)** — во время инференса выбирается/адаптируется LoRA-подобная дельта весов "на лету" под задачу.
- **Larimar (IBM, 2024)** — внешняя память с эпизодами, запись/чтение через дифференцируемые операции, не полный fine-tuning.

### Что важно продумать

**1. Что является "лоссом" для градиентного шага?**
- Loss = "предскажи следующий токен лучше" → обычный continual learning в миниатюре, со всеми рисками (переобучение на последний пример, забывание предыдущих).
- Loss = "минимизируй расстояние между e_t и уже записанным похожим вектором" (contrastive/metric learning) → организация памяти, а не давление на выходы модели. **Рекомендован этот вариант** — self-supervised организация пространства памяти.

**2. Скорость записи vs чтения — разделять архитектурно.** Чтение (retrieval) — быстрый forward pass с cosine similarity/attention над векторами памяти, без градиента. Запись (обновление LoRA) — реже, по событию (детектор решил "это важно"), возможно асинхронно/в фоне после ответа, не блокируя генерацию.

**3. Забывание всё равно есть, просто по-другому.** LoRA-дельта — тоже непрерывные веса; продолжая писать в неё градиентами, старые записи постепенно "стираются" (классическая проблема continual learning). Дискретный тернарный вариант устойчивее именно потому, что каждая ячейка адресуется отдельно. Пути решения:
- расширять LoRA-память (несколько независимых низкоранговых блоков, каждый под свою "область" фактов, выбираемых через routing — похоже на MoE над памятью);
- либо периодически замораживать старые LoRA-блоки и создавать новые (версионирование).

**Итоговый открытый вопрос упрощённой версии**: не "как писать", а "какой лосс двигает запись" и "как не дать новым записям стирать старые".

## 12. Выравнивание пространства памяти с основной моделью (дистилляция эмбеддингов)

### Почему это важно
Если пространство памяти обучать с нуля независимо — оно не связано с тем, как основная модель "понимает" слова; проектор должен изучать семантику заново, глядя только на пары (h_t, событие записи). Долго, шумно, требует много данных.

Если дистиллировать эмбеддинг основной модели в память-сеть (memory-encoder учится приближать те же вектора, что выдаёт основная модель):
- пространство памяти "говорит на том же языке" с самого начала;
- проектор становится почти identity-функцией — резко снижает риск потерь/искажений при переводе туда-обратно;
- это ровно то, что делают в **model stitching / representation alignment** исследованиях — разные независимо обученные сети часто приходят к похожим latent-пространствам с точностью до линейного преобразования (**"Platonic Representation Hypothesis", 2024**).

### Два варианта дистилляции
- **А. Дистилляция на уровне эмбеддингов токенов** — память-сеть учится через MSE/cosine loss воспроизводить вектора основной модели для тех же токенов/фраз. Дёшево и быстро, но фиксирует только статичную семантику слов, не контекстную.
- **Б. Дистилляция на уровне контекстных скрытых состояний** — сеть приближает h_t основной модели *в контексте*. Ближе к реальной задаче (память пишется по скрытому состоянию в моменте диалога), но дороже (нужны оба forward pass параллельно на большом числе контекстов).

Рекомендация: начать с А, расширять до Б при необходимости.

### Дрейф пространства во времени
Если дистиллировать один раз и заморозить — пространство останется привязанным к той версии основной модели. Если основную модель дообучат, латентное пространство сместится, память "устареет" (та же проблема дрейфа, отложенная во времени).

**Решение**: не дистиллировать раз и навсегда, а держать лёгкий **continual-alignment лосс** — небольшой довесок к обучению LoRA-памяти, который постоянно чуть-чуть подтягивает пространство памяти к текущему пространству основной модели (например, раз в N записей — маленький шаг дистилляции).

### Полная дистилляция знаний (Hinton et al.) — это НЕ то, что нужно
Классическая дистилляция — маленькая модель-студент воспроизводит **весь выход** большой модели (распределение вероятностей по всем токенам, softmax с температурой). Тяжело, требует много данных, копирует поведение всей сети. Не нужно — нужно только чтобы **пространство векторов** было согласовано.

### Что нужно на самом деле: alignment эмбеддингов
Берёшь пары одинаковых входов, пропускаешь через основную модель → `e_main`, через свою память-сеть → `e_mine`. Учишь сеть (или только проектор) минимизировать расстояние:

```
loss = 1 - cosine_similarity(e_main, e_mine)
```
(или MSE, если нужно строже по величине). Работает для любой архитектуры памяти-сети (MLP, маленький трансформер) — главное, вектор той же размерности (или с проекцией к ней).

Специальные слои нужны только если нужно сохранить **структуру пространства** (не только похожие точки похожи, но и отношения между векторами) — тогда contrastive loss с негативными примерами, или **CKA/relational loss** (сравнивают расстояния между парами векторов в обоих пространствах, а не сами вектора).

### Практическая схема (без спец-слоёв)
1. Набор текстов/фраз/токенов.
2. Прогнать через основную модель → `e_main` для каждого (последнее скрытое состояние или эмбеддинг токена).
3. Прогнать те же тексты через свою память-сеть → `e_mine`.
4. Учить только проектор (или всю сеть, если маленькая) через cosine-loss, чтобы `project(e_mine) ≈ e_main`.
5. После этого проектор — "переводчик" между пространствами; дальше строится LoRA-память поверх выровненного пространства.

Делается как отдельный препроцессинг-этап до основного обучения памяти (плюс опционально лёгкий continual-режим).

### Функция vs база данных
Дистиллированная мини-сеть не становится "базой данных" в смысле "конкретные вектора лежат построчно". Сеть учится **функции** — отображению "вход → вектор в согласованном пространстве".
- **Векторная БД** — таблица: слово → фиксированный вектор, лежащий явно (как в Excel). Новое слово — новая строка.
- **Дистиллированная мини-сеть** — параметрическая функция, выдающая вектор для *любого* (в т.ч. невиданного) входа, потому что выучила общую структуру, а не таблицу. Ближе к энкодеру, не к базе — генерализует, а не хранит.

**Итоговая двухслойная архитектура:**
```
Слой 1 (дистиллированный энкодер) — выучил "геометрию языка",
                                      статичный, почти не меняется после обучения
        │
        ▼
Слой 2 (LoRA-память / явная таблица) — растёт и наполняется
                                         конкретными фактами/событиями со временем
```
Если писать новые факты сразу в веса Слоя 1 — риск размыть выровненную геометрию (придётся передистиллировать). Слой 1 — "словарь смыслов" (обучается редко), Слой 2 — "дневник событий" (растёт постоянно, ведёт себя как база данных).

## 13. Суперпозиция и разреженные признаки (SAE)

### Эмбеддинг как таблица
`nn.Embedding` — по конструкции таблица: индекс токена → строка-вектор. "Векторная БД" по определению, ещё до разговоров про суперпозицию — это архитектурный факт с начала трансформеров.

### Суперпозиция — не "ортогональные операции", а способ упаковки
Anthropic, **"Toy Models of Superposition" (2022)**, затем **"Towards Monosemanticity" / "Scaling Monosemanticity"**:
- Размерность вектора эмбеддинга (768/4096) намного меньше числа реальных концептов, которые модель хочет закодировать (могут быть миллионы).
- Признаки размещаются не по отдельным осям, а по **почти ортогональным** (не строго!) направлениям — по лемме Джонсона-Линденштрауса, в пространстве большой размерности можно уместить экспоненциально много почти непересекающихся векторов.
- Платится "интерференцией" — редкие признаки слегка мешают друг другу, но т.к. активны редко одновременно, ошибка терпима.

Это способ **упаковки информации**, геометрический трюк, не отдельная вычислительная операция.

### Sparse Autoencoder (SAE) / dictionary learning
Сырой эмбеддинг/скрытое состояние — плотный, суперпозиционный, полисемантичный вектор (одна ось кодирует десятки не связанных смыслов). Использовать напрямую как ключ памяти неудобно — расстояния не соответствуют чистому "это про одно и то же".

**SAE**: берёшь плотный вектор → обучаешь автоэнкодер с гораздо большей (избыточной) размерностью на выходе + условие разреженности (активны немного признаков одновременно). Разворачивает суперпозицию в набор более монозначных ("monosemantic") направлений, каждое ближе к одному интерпретируемому понятию. Именно это направление Anthropic исследовали на реальных моделях (Claude) — находили отдельные интерпретируемые признаки внутри суперпозиции.

### Почему это полезно для памяти
- Каждый активный признак после SAE ближе к "одному смыслу".
- Ключи памяти строятся по разреженным признакам — похожесть по ключу реально означает смысловую похожесть, а не совпадение из-за интерференции.
- Естественная интерпретируемость: видно, какой признак сработал и вызвал запись в память (полезно для отладки и для детектора "что важно запомнить").

## 14. Относительные представления и передача латентного вектора между сетями

### Model stitching / relative representations
**Moschella et al., "Relative representations" (2023)**: если перевести внутренние представления двух независимо обученных сетей в пространство *относительных расстояний* (не абсолютных координат), куски одной сети можно "сшивать" к другой почти без потерь — передавать "вектор мышления" одной модели в другую через обучаемую или даже необучаемую проекцию.

**Vec2Vec / unsupervised embedding translation (2024)**: перевод эмбеддингов из одного пространства в другое **вообще без пар примеров** — просто выравниванием геометрической структуры.

**Coconut / "Chain of Continuous Thought" (Meta, 2024)**: вместо пошагового рассуждения через дискретные токены (chain-of-thought) модель передаёт своё скрытое состояние (вектор мышления) обратно себе на следующий шаг напрямую, без перевода в текст. Эффективнее — дискретный токен = узкое горлышко (несколько бит), вектор несёт на порядки больше информации.

Родственно также **soft prompts / prompt tuning** — модели скармливается не текстовый промпт, а обученный непрерывный вектор.

### Почему это ценно
Токен — узкое горлышко. Когда модель А передаёт модели Б результат размышления через текст — это лоссовое сжатие богатого внутреннего состояния в человеко-читаемую, но информационно бедную форму. Прямая передача вектора обходит горлышко.

### Подвох: потеря интерпретируемости
Когда А говорит Б текстом — человек может прочитать, что происходит. Когда передаётся сырой вектор — нельзя проверить, что реально передалось, не появился ли sycophancy/дрейф смысла (вектор от А может значить одно, Б интерпретирует иначе, если пространства не идеально выровнены). Это реальная тема AI safety — прозрачность рассуждений и **"cross-model steganography"** (модели могут научиться передавать скрытую информацию друг другу, не проявляющуюся в видимом тексте) — обсуждается как риск в multi-agent системах и латентной коммуникации.

**Практический вывод для архитектуры памяти**: если векторы передаются между "основной моделью" и "памятью" напрямую (не через текст) — теряется возможность легко проверить/отладить, что записывается и читается. Стоит закладывать сознательно (например, держать возможность декодировать вектор памяти обратно в текст для отладки, даже если в проде не используется).

### Алгоритм относительных представлений (конкретно)

**Шаг 1. Выбрать якоря (anchors)** — набор точек (100–1000 примеров текста/слов), одинаковых для обеих сетей.

**Шаг 2. Эмбеддинги якорей для каждой сети:**
```
Сеть А: anchor_1 → a_1, anchor_2 → a_2, ..., anchor_N → a_N
Сеть Б: anchor_1 → b_1, anchor_2 → b_2, ..., anchor_N → b_N
```
`a_i` и `b_i` живут в *разных* пространствах (разная размерность/геометрия) — это нормально, они больше не сравниваются напрямую.

**Шаг 3. Новый вектор → относительное представление** (вектор сходств с якорями, не абсолютные координаты):
```
r_A(x) = [cosine_sim(embed_A(x), a_1), ..., cosine_sim(embed_A(x), a_N)]
r_Б(x) = [cosine_sim(embed_Б(x), b_1), ..., cosine_sim(embed_Б(x), b_N)]
```

Если якоря — одни и те же смысловые точки, `r_A(x)` и `r_Б(x)` оказываются похожи, даже если `embed_A(x)` и `embed_Б(x)` в изначально несравнимых пространствах (разная размерность, поворот, масштаб). Относительное расположение точек ("форма" облака) у семантически осмысленных пространств похоже, даже когда абсолютные координаты — нет.

### Применение к векторной БД
1. Общий набор якорей (можно сами фразы из БД).
2. Прогнать якоря через оба пространства (БД-энкодер и своя сеть).
3. Перевести вектора БД в относительное представление (относительно якорей из БД).
4. Перевести вектора своей сети в относительное представление (относительно тех же якорей, но через свой энкодер).
5. Сравнение/поиск между сетями **без обучения проектора вообще** — оба представления уже в общих сравнимых координатах.

Это "нулевое обучение" версия того же, что даёт LoRA-проектор с градиентом: дистилляция/проектор с градиентом — точнее и гибче, но требует данных и обучения; относительные представления — грубее, но работают сразу, без backprop, при наличии общего набора якорей.

### Практический вывод: комбинировать оба подхода
- **Относительные представления** — быстрый, не требующий обучения baseline/fallback (особенно на старте, когда данных для проектора ещё нет).
- **LoRA-проектор с градиентом** — точная, дообучаемая надстройка, когда накопится достаточно пар примеров.

Разница по цене: относительные представления — O(N) скалярных произведений (N = число якорей) на новый вектор, дёшево. Обучаемый проектор дороже на обучении, но дешевле на инференсе (один матричный проход вместо N сравнений), если N большое.
