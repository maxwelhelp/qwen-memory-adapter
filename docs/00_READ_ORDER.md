# Карта чтения — с чего начинать агенту

Порядок: сначала ЭТОТ файл → потом план действий → мастер-документ по требованию →
исходники по требованию → код.

---

## 1. Идти по этому файлу

**`PLAN_MEMORY_V2.md`** — актуальный план действий, что делать ПРЯМО СЕЙЧАС.
Содержит: найденное расхождение докстринга и кода в v5 (разобрать первым), 4 пункта,
требующих решения пользователя (не трогать без спроса), приоритизированную таблицу
экспериментов (§8), методологические риски (§10). Это рабочий документ — им и
руководствоваться при следующем шаге.

Если план выполнен/устарел — писать новую версию (`PLAN_MEMORY_V3.md` и т.д.), не
затирать старую: история решений должна быть видна.

---

## 2. Читать по требованию (справочник, не план действий)

**`MEMORY_MASTER.md`** — полный свод всех 11 исходных файлов в одном месте: карта трёх
направлений (A — MLP-память/веса=контекст, B — скоринг KV-эвикции, C — россыпь идей),
архитектуры, все результаты с числами, все технические уроки/провалы и почему, внешние
референсы, глоссарий. Использовать как индекс/энциклопедию, когда нужен контекст «а
почему мы вообще так решили» или «что уже пробовали и не сработало» — НЕ как источник
команд к действию (там нет приоритетов, это архив).

Навигация внутри него — оглавление в начале файла, разделы 1-10.

---

## 3. Исходники — читать точечно, когда мастер-документа не хватает

Все 11 файлов ниже уже пересказаны в `MEMORY_MASTER.md`. Открывать напрямую только если
нужна точная формулировка/код/цифра, которую сжатый пересказ мог огрубить.

### Направление A — MLP-память (веса = контекст), главное направление
| Файл | Что внутри |
|---|---|
| `memory_layer_v2.md` | Исходный план архитектуры направления A (до того, как что-то пошло не по плану) |
| `ARCHITECTURE.md` | Итоговая РАБОЧАЯ архитектура (та, что даёт 85%) — самый короткий и точный источник по текущей рабочей схеме |
| `REPORT_MEMORY_MLP.md` | Честный разбор: план vs реализация, почему bilevel не сошёлся (7 прогонов), разбор кода Titans, чем отличается наша схема |
| `RESULTS.md` | Все цифры экспериментов направления A по шагам (know/not-know classifier, механика на синтетике, межсессионный тест, MLP-слоты) |
| `titans_qwen.md` | Первая версия идеи + отдельно разбор логических дыр (frozen_loss не измеряет «знает из весов», один M(q)=каша, синтетика≠реальные данные) — читать вторую половину файла (после «Разбор: логические дыры и фиксы»), первая половина устарела |
| `titans_qwen2.md` | L_fast/L_slow (двухуровневая память), persistent tokens — НЕ реализовано, идея на будущее |

### Направление B — скоринг KV-кэша (эвикция), параллельная ветка
| Файл | Что внутри |
|---|---|
| `kv_mechanisms.md` | Референс всех механик эвикции/добавления из чужих кодовых баз (H2O, SnapKV, KVzap, Titans) — читать как справочник терминов, не как план |
| `annotator_teacher.md` | Идея третьей головы скоринга (аннотатор с будущим вопросом) — тест-взгляд пройден (100%), полный датасет не собран |
| `tiered_memory_mlp.md` | Трёхуровневая память (кэш+база+retrieval) — развитие скоринга, не начато |

### Направление C — общая россыпь, банк идей, ничего не реализовано
| Файл | Что внутри |
|---|---|
| `01-memory-architecture-kv-fastweights.md` | Самый широкий обзор: fast weights, тернарная память, LoRA-память, SAE, relative representations — читать, когда нужна альтернатива текущему подходу, не для текущих задач |
| `04-online-mlp-memory-qwen.md` | Детальный дизайн online-memory с explicit gate и active-neuron sparsity — отдельная, не пересекающаяся с текущим кодом ветка |

**Итого по направлению C: если сейчас работаем над направлением A (текущий код v5) — эти
два файла НЕ читать, если не идёт речь о смене архитектуры целиком.**

## 4. Код

**`v5_train_memory_distill.py`** — текущая лучшая рабочая версия направления A
(MLP-слоты, alignment → η-голова → заморозка → дистилляция). Аудит этого конкретного
файла — в `PLAN_MEMORY_V2.md` §1-2. Не запускать правки поверх него, пока не решён
пункт §1 плана (logit-shift vs input-injection) — это меняет саму цель обучения.
