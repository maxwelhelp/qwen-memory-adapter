# Онлайн-память (MLP) для Qwen: дистилляция пространства + sparse-обновление активных нейронов + gated-инъекция

Дизайн-документ отдельного обучаемого модуля памяти поверх замороженной Qwen2/2.5.
Цель: маленькая MLP-сеть, которая **непрерывно доучивается прямо во время инференса**
именно тому, чего не знает основная сеть, **сохраняет это навсегда** (не забывает между
запросами), но умеет вытеснять бесполезное. Основная сеть весь документ считается
замороженной — учится только память.

Опирается на: `02-knowledge-transfer-weight-generation.md` (варианты переноса, ROME/MEMIT,
Procrustes), `cross_model_alignment_pipeline.md` (выравнивание пространств),
`03-circuit-analysis-toolkit-qwen2.md` (готовая инфраструктура atlas/patch/`rel_err`).

---

## 0. Общая схема (что откуда куда течёт)

```
                     ┌─────────────────────────┐
prompt ──► Qwen (frozen) ──► hidden state h_L (слой L) ──► gate(h_L, uncertainty) ──┐
                     └─────────────────────────┘                                    │
                                                                                     ▼
                                                              ┌───────────────────────────┐
                                                              │   Memory MLP (обучаемая)   │
                                                              │  - читает h_L (в общих     │
                                                              │    координатах)            │
                                                              │  - выдаёт delta-вектор      │
                                                              │  - сама обновляется online  │
                                                              └───────────────────────────┘
                                                                             │
                                                              gate * delta ──┘
                                                                             ▼
                                                        h_L' = h_L + gate * delta  (residual)
                                                                             │
                                                                             ▼
                                                        дальше по слоям Qwen как обычно
```

Три независимых механизма, которые часто путают — важно развести сразу:

| Механизм | Что меняется | Насколько постоянно |
|---|---|---|
| **Инъекция в residual** (`h_L' = h_L + gate*delta`) | Ничего в весах Qwen. Добавка живёт только в рамках этого forward pass. | Эфемерно — нужно повторять каждый раз |
| **Обучение Memory MLP** (online, каждый шаг) | Веса *памяти*, не Qwen | Постоянно, накопительно — это и есть «обучение при инференсе» |
| **Консолидация в Qwen** (опционально, п.7) | Веса самой Qwen (ROME-стиль patch) | Постоянно, но это отдельный, более рискованный шаг |

На ваш вопрос «мне кажется, инъекция может менять веса» — нет, **инъекция сама по себе
не меняет веса Qwen**, это просто арифметика в residual stream на конкретном forward pass
(как activation steering). Меняются веса **памяти** — вот где реально происходит «учёба».
Если захотите, чтобы что-то осело в самой Qwen навсегда — это отдельный шаг (п.7), не то
же самое, что инъекция.

## 1. Компонент A — дистилляция embedding-пространства (подготовительный шаг, один раз)

Прежде чем память сможет читать `h_L` и писать обратно совместимый delta, у неё должно
быть **то же координатное пространство**, что у Qwen на слое L. Два варианта:

- **Procrustes** (из файла 2/pipeline) — если память архитектурно близка к Qwen (например,
  инициализирована как маленький срез той же архитектуры) — закрытое решение через SVD,
  без обучения. Дёшево, но работает только если пространства уже похожи.
- **Дистилляция** — если хотите маленькую независимую сеть (не урезанную копию Qwen),
  обучаете её представление приближаться к `h_L` Qwen на anchor-корпусе:

```python
# один раз, офлайн, до начала онлайн-фазы
for x in anchor_corpus:
    h_qwen = qwen.forward_to_layer(x, L).detach()      # заморожен
    h_mem  = memory_encoder(x)
    loss = distance(project(h_mem), h_qwen)              # MSE / cosine
    loss.backward()                                       # обучается только memory_encoder
```

Это **другой вид обучения**, чем обычный LM-лосс: прямая регрессия на вектор, не
авторегрессия по словарю — на порядки дешевле полного файнтюна. После этого шага
Прокруст на будущее не нужен — совместимость пространств уже «зашита» в память по
построению.

**Рекомендация**: если память = маленький срез той же Qwen-архитектуры (тот же
tokenizer/hidden dim того же семейства) — берите Procrustes, он почти бесплатный.
Если хотите гибкую независимую по размеру сеть — дистилляция, но это разовая
инвестиция, которая окупается на множестве последующих сессий.

## 2. Компонент B — активные нейроны: нужен ли отдельный forward сначала?

Да, короткий forward нужен — но это не дополнительная дорогая стадия, а переиспользование
уже посчитанной арифметики. Последовательность на каждом шаге (каждом токене или
каждом промпте, в зависимости от гранулярности, которую выберете):

```python
h = qwen.hidden_state_at_layer(x, L)              # уже вычислено основным forward
a = silu(Wg_mem @ h) * (Wu_mem @ h)                # rank-1 атом на каждый нейрон памяти
                                                     # — то же самое, что mlp_atom_matrix
                                                     # в тулките, только для сети памяти
active_mask = topk_by_abs(a, k) | (|a| > percentile_thresh)
```

`active_mask` используется дважды:
1. **На чтение** — какие нейроны реально участвуют в текущем выводе памяти (обычный
   sparse forward, часть нейронов можно занулять для эффективности).
2. **На запись** — какие строки/столбцы весов памяти вообще разрешено трогать на этом
   шаге (см. п.4). Именно это отвечает на «сначала нужно увидеть активные нейроны, а
   потом решать, что обновлять» — да, ровно в этом порядке, и это дёшево, потому что
   `a` вы и так считаете при обычном forward pass памяти.

## 3. Компонент C — сигнал «surprise» (что писать в память)

Не обучайте память на всём подряд — иначе она просто станет вторым языковым лоссом без
пользы. Сигнал surprise должен отражать **именно «основная сеть здесь плоха»**:

| Сигнал | Как считать | Стоимость |
|---|---|---|
| **Loss/perplexity основной сети на текущем токене** | `-log p_qwen(x_true \| context)` | Бесплатно — уже считается |
| **Энтропия распределения Qwen** | `entropy(softmax(logits_qwen))` | Бесплатно |
| **Semantic entropy** (Kuhn et al., 2023) | Несколько сэмплов + кластеризация по смыслу | Дороже (N генераций), но точнее отделяет «не знает факт» от «колеблется в формулировке» |
| **Разрыв logit lens между средним и последним слоем** | `KL(p_mid \|\| p_final)` | Средне — доп. проход через unembedding на промежуточном слое |
| **Градиент собственного лосса памяти** (как в Titans) | `‖∇_θ_mem loss‖` в момент записи | Считается заодно с backward |

**Практичный минимум для старта**: entropy Qwen + perplexity на true-токене (обе бесплатны,
уже есть в forward pass). Если `surprise` низкий (Qwen уверена и права) — **не пишем**,
экономим ёмкость памяти. Semantic entropy — апгрейд второй итерации, когда MVP заработает.

## 4. Правило записи (online update) — delta-rule + forgetting

Схема в духе Titans (associative memory update), но ограниченная только на `active_mask`
из п.2:

```python
S = active_mask                      # индексы активных нейронов памяти на этом шаге
target = teacher_signal(x)           # см. ниже — откуда брать "правильный" вектор

lr_t   = eta * surprise_t            # чем больше surprise — тем сильнее пишем
decay  = lambda_forget               # забывание — тянет неиспользуемые веса к нулю

# обновляется ТОЛЬКО подматрица памяти, отвечающая индексам S
W_mem[S] = (1 - decay) * W_mem[S] + lr_t * outer(h[S], target)
```

- `teacher_signal(x)` — источник «правильного» направления: может быть true-токен
  из данных (self-supervised), может быть выход более сильной модели (дистилляция «на
  лету»), может быть выход causal-tracing атласа для конкретного факта (см. файл 2, п.9) —
  выбор зависит от того, откуда вы физически берёте «то, чего Qwen не знает».
- **Forgetting двух типов**:
  1. Мягкий decay каждый шаг (строка выше) — тянет редко используемые веса к нулю,
     реализует «неполезное забывается само».
  2. Жёсткая чистка — счётчик использования на нейрон, если нейрон не входил в
     `active_mask` N шагов подряд — сбросить/переиспользовать под новый факт (реюз
     слотов памяти, конечная ёмкость не растёт бесконечно).

## 5. Структурная разреженная LoRA — конкретная реализация

Вместо dense `W_mem` держите low-rank дельту `ΔW = B @ A`, но с маской по активным
индексам:

```python
# B: [D, r], A: [r, D] — обычная LoRA пара, но обновляются только строки в S
B[S, :] += lr_t * surprise_t * grad_B[S, :]
A[:, S] += lr_t * surprise_t * grad_A[:, S]
```

Плюсы против dense-обновления из п.4:
- Меньше параметров реально трогается за шаг → меньше интерференции с фактами на других
  нейронах той же памяти (та же проблема суперпозиции, что и в основной сети).
- Дешевле по памяти/градиентам — низкий ранг `r` вместо полной матрицы.
- Естественно ограничивает «ёмкость на факт» — если ранг мал, а фактов много, старые
  дельты будут вытесняться decay'ем автоматически, что и нужно для «забывания
  неполезного».

Это прямое расширение "Практичного гибрида" из файла 2 (LoRA только на region) — только
region здесь определяется не заранее (causal tracing на всей сети), а динамически на
каждом шаге через `active_mask`.

## 6. Инъекция вывода: вектор в hidden state или текст?

**Рекомендация: вектор в hidden state, не текст.** Причины:

| | Vector injection (residual) | Text injection (RAG-стиль) |
|---|---|---|
| Точность | Прямая, на уровне направления в пространстве | Ограничена тем, что вообще вербализуемо |
| Стоимость | Одна арифметическая операция сложения | Съедает токены контекста, доп. forward |
| Обратимость/безопасность | Легко тестировать через `rel_err` до/после (уже есть в тулките) | Труднее измерить точечный эффект |
| Годится как fallback | — | Да, если vector injection нестабилен — грубее, но надёжнее и проще дебажить |

Практически: `h_L' = h_L + gate * delta`, слой L выбирается там же, где обычно ищут
factual recall circuits (middle layers, по ROME/Dai et al.) — не обязательно последний.

## 7. Когда инжектировать — от чего зависит gate

Это ключевой открытый вопрос из вашего сообщения, и он решается **комбинацией двух
источников**, не одним:

```
gate = f( uncertainty(h_L, prompt) , similarity(query, memory_keys) )
```

1. **От состояния Qwen (uncertainty)** — та же entropy/logit-lens-gap из п.3. Если Qwen
   уже уверена и, скорее всего, права — инъекция не нужна и может только навредить
   (испортить то, что и так работало). Инжектировать **только когда Qwen сомневается**.
2. **От релевантности памяти (similarity)** — cosine similarity между текущим `h_L`
   (или его relative representation, см. Procrustes/anchor-подход) и ключами, хранимыми
   в памяти. Если ничего похожего в памяти нет — gate = 0, инъекция бессмысленна, даже
   если Qwen не уверена.
3. **Не от промпта напрямую** (сырого текста) — а от **hidden state**, потому что именно
   он уже учитывает контекст на нужном уровне абстракции; сырой промпт для gate — более
   шумный и дорогой сигнал (пришлось бы отдельно его кодировать).

MVP-версия gate (без обучения, эвристика для первого теста):
```python
gate = 1.0 if (entropy_qwen > tau_uncertain and max_sim(h_L, mem_keys) > tau_relevant) \
       else 0.0
# затем можно заменить на непрерывный: gate = sigmoid(w1*entropy + w2*max_sim - b)
```

Финальная (обучаемая) версия — маленькая gate-сеть, тренируемая вместе с памятью на
сигнале «стало ли лучше после инъекции» (тот же принцип, что оценка `rel_err` в тулките,
только как обучающий сигнал, а не только диагностика).

## 8. Приоритизированный план тестирования (от самого дешёвого/безопасного к амбициозному)

Каждый следующий этап добавляется только после того, как предыдущий проверен
существующими метриками (`rel_err`, `downstream_amplification` из тулкита).

1. **MVP — чистый retrieval, без обучения памяти вообще.**
   Простая растущая key-value таблица (без Memory MLP), эвристический gate из п.7,
   vector injection. Цель: проверить, что сам механизм gate+injection не ломает Qwen
   и вообще помогает на очевидных примерах. Самый дешёвый и диагностически самый важный
   шаг — если это не работает, сложная память тоже не спасёт.
2. **Titans-style Memory MLP, dense update (без active-neuron маски).**
   Добавить онлайн-обучение памяти по правилу из п.4, но без ограничения на активные
   нейроны — проверить, что online-обучение вообще стабильно (не расходится, не
   деградирует со временем).
3. **Добавить active-neuron маску (п.2, п.4) — ablation против шага 2.**
   Сравнить: с маской vs без — меньше интерференция между фактами? Быстрее сходится?
   Это первая точка, где стоит по-настоящему замерить разницу количественно.
4. **Structured sparse LoRA + forgetting/decay + usage-based pruning (п.5).**
   Проверка на длинном потоке: старое полезное знание не вымывается, шум/redunant
   факты действительно забываются (метрика: точность на held-out фактах через N шагов
   после записи и после N шагов без обращения к ним).
5. **(Опционально, самый рискованный) Периодическая консолидация в саму Qwen.**
   Факты, которые долго и стабильно оказываются полезны (surprise стабильно падает
   после N подкреплений) — «выпускной экзамен» на постоянную запись в веса Qwen
   ROME-стилем (замкнутая формула, точечно, как в файле 2). Мост между «временная
   память» и «навсегда в весах» — но именно поэтому делать последним, после того как
   более дешёвые этапы подтверждены.

## 9. Честный ответ на «какой вариант самый эффективный»

Без замеров на реальных числах ответить однозначно нельзя — но структура приоритизации
в п.8 сама по себе является ответом: **начинать с шага 1**, потому что он самый дешёвый
диагностический тест сразу двух критичных допущений — (а) что gate вообще можно построить
разумно из entropy+similarity, и (б) что injection в residual не ломает Qwen на
`rel_err`. Если оба подтверждаются на MVP — каждый следующий шаг это чисто инкрементальное
усложнение (Titans-обновление → sparsity → forgetting → консолидация), и на каждом шаге
у вас уже есть готовая метрика из тулкита, чтобы решить, окупается ли усложнение, а не
гадать заранее.
