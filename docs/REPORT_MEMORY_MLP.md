# Отчёт: план (MLP-память) vs реализация + как вернуться к плану

Дата: 2026-08-03. Статус: честный разбор отклонений, изучение Titans-кода, план возврата.

## 1. План (memory_layer_v2.md + titans_qwen.md)

1. Память = **MLP M_θ (896→3584→896)**, веса = записанный контекст (Titans-стиль).
2. **Запись на инференсе**: k_t, v_t проекции; **η-голова** (сила записи),
   **γ-голова** (забывание); шаг `θ ← θ·(1−γ_t) − η_t·∇||M(k_t)−v_t||²`.
3. Чтение `M_θ(q)`, подмешивание `h_final = h_final + g·W_out(M_θ(q))`.
4. Обучение: дистилляция на y_attn (внимание Qwen), bilevel create_graph.
5. Сигнал новизны: классификатор know/not-know (шаг 1).
6. 4c: персистентность между сессиями.

## 3. Отклонения от плана (что сделано ДРУГИМ способом)

1. **НЕ MLP**: финальная версия — 32 ЛИНЕЙНЫХ слота (Linear 896→896).
2. **Запись НЕ обучаемая**: bilevel-градиенты не доходят (7 прогонов, mix≈0) →
   слоты заморожены; запись = необучаемая механика самовосстановления M(h)≈h;
   обучается только извлечение (W_route, W_out, g). η/γ-головы НЕ обучены.
3. **Учитель НЕ y_attn**: заменён на Δ = h_out(с контекстом) − h_out(без),
   затем на сдвиг логпробов кандидатов (6 чисел) вместо подмешивания в hidden.
4. **Добавлено сверх плана**: alignment-фаза (M(h)≈h), обучаемая маршрутизация W_route.

## 4. Почему MLP не работал у меня (разбор провалов)

### 4.1 Первая попытка (train_mlp_memory.py, до этой сессии)
MLP схлопнулся к нулю. Причины:
- запись 2 шагами на ВЕСЬ контекст — слишком мало шагов для запоминания;
- нет η/γ-голов — веса обновлялись равномерно и «затирали» друг друга;
- нет учителя — память не знала, ЧТО отдавать (нет дистилляционного таргета);
- RMSNorm-насыщение tanh в архитектуре слота.

### 4.2 В этой сессии (дистилляция)
- Нелинейные слоты на синтетике — слабее линейных (−16% vs −44%): ОДИН шаг
  записи на пару не хватает нелинейной сети (нужны итерации записи).
- **Bilevel-градиенты через запись не доходят**: клоны весов (clone) обрывают
  граф для ранних шагов; mix ≈ 0; val_acc = шанс (0.17) — 7 прогонов подряд.
  Фикс-обход: заморозка слотов (запись = механика, извлечение = обучаемое) →
  сразу val_acc 0.85-0.88, межсессионный тест 34/40.
- Подмешивание вектора в hidden требует космической точности: Δ~150 при ||h||~15,
  norm() давил и сигнал, и градиенты в ~150 раз → выход в логпроб-пространство
  кандидатов (6 чисел) — прямое управление метрикой.

### 4.3 Почему в Titans это работает (изучение кода titans-pytorch/neural_memory.py)
- Память = **MemoryMLP** (depth=2, expansion=4), веса = память; чтение —
  функциональный прогон MLP с записанными весами (functional_call).
- **Запись — vmap per-sample градиенты** ассоциативного лосса ||M(k)−v||²:
  `per_sample_grad_fn = vmap(grad(forward_and_loss))` — ВСЕ токены разом,
  и это внутри **higher-order autograd-графа** (torch.func) — градиенты
  текут в θ₀, проекции k/v и η/γ-головы (полный bilevel, не обрезанный).
- **η-голова**: adaptive_lr = σ(Linear(seq))·max_lr — применён как ВЕС ЛОССА
  (loss·η) — «как сильно учиться на токене» (эквивалент нашего η, но обучаемый).
- **γ-голова**: decay_factor = σ(Linear(chunk)) — забывание через
  assoc_scan(1−γ, update) — геометрическое накопление, стабильно.
- **momentum**: S_t через assoc_scan с адаптивным затуханием (обучаемым).
- Успех обеспечивают: совместное end-to-end обучение модели и памяти,
  higher-order vmap-градиенты, обучаемые η/γ/momentum, ассоциация k→v
  (НЕ самовосстановление), огромный масштаб данных.
- Наш случай: Qwen заморожена, дистилляционный сигнал вместо языкового лосса,
  маленький датасет, обрезанный bilevel (клоны) — сигнал до записи не доходит.

## 5. Alignment — к чему применялся (ответ на вопрос)

Alignment применялся к ЛИНЕЙНЫМ слотам: фаза 1 учила их воспроизводить
скрытые состояния Qwen (M(h)≈h) — «слоты говорят на языке Qwen», проекция
становится почти identity. При возврате к MLP alignment применяется к
MLP-слотам (нелинейная аппроксимация пространства Qwen — даже лучше).
В Titans аналогии нет отдельной фазы — у них пространство выравнивается
самим end-to-end обучением; у нас (замороженная Qwen) alignment — замена.

## 6. Как MLP устроен в Titans (по коду) и наша адаптация

```
Titans (neural_memory.py):
  keys = to_keys(x); values = to_values(x)          # проекции (Linear+bias=False+активация)
  η_t = σ(to_adaptive_step(x))·max_lr               # обучаемая скорость записи
  γ_t = σ(to_decay_factor(chunk))                   # обучаемое забывание
  S_t = vmap(grad(||M(k)−v||²·η_t))                 # per-sample градиенты, higher-order
  update = assoc_scan(1−γ, assoc_scan(η_mom, S))    # momentum + forgetting
  W_t = W_0 + Σ update                              # веса = память
  чтение: M(q) = functional_call(model, W_t, q)     # MLP с записанными весами
  обучение: языковой лосс → bilevel через torch.func (higher-order)

Наша адаптация (план, 3 этапа):
  3.1 MLP-слоты в рабочей схеме (без bilevel):
      слот = Linear(896→256)→GELU→Linear(256→896) (MemoryMLP-стиль);
      alignment к MLP-слотам; запись — нормированные шаги самовосстановления
      (необучаемая механика); извлечение — W_route + W_out(896→6) + g.
  3.2 Обучаемая запись БЕЗ bilevel:
      η_t = f(classifier_know_notknow(h_t)) — классификатор шага 1 (92%) —
      «novelty гейтит θ_t» (titans_qwen.md); γ_t — обучаемый байас +
      decay по времени; momentum через assoc_scan (как Titans).
  3.3 Полный Titans-стиль (опционально, с тёплого старта):
      vmap per-sample градиенты (torch.func, higher-order) на MLP-памяти,
      ассоциация k→v (to_keys/to_values), η/γ/momentum обучаемые;
      если bilevel не сойдётся — остаёмся на 3.1+3.2 (рабочая схема).
```

## 7. План действий (чётко)

1. **3.1 (30-60 мин)**: линейные слоты → MLP-слоты (896→256→896) в рабочей схеме.
   Ожидание: alignment точнее (нелинейная аппроксимация), прирост к 85%.
2. **3.2 (1-2 ч)**: η-голова через классификатор know/not-know (готов!) +
   γ-декей + momentum (assoc_scan) — запись становится «обучаемой» без bilevel.
   Связка: память пишет сильнее «неизвестное», слабее «известное», забывает шум.
3. **3.3 (эксперимент)**: полный Titans-стиль (vmap higher-order bilevel) —
   только если 3.1+3.2 стабильны; иначе оставляем рабочую схему.
4. Решение по подмешиванию: остаётся логпроб-сдвиг (работает) — векторное
   подмешивание в hidden вернуть только если 3.x даст запас точности.
5. L_fast/L_slow (titans_qwen2.md) — поверх 3.2 (порог записи = novelty).

## 8. Честная оценка

Рабочая система (34/40, 85%) — НЕ MLP-память из плана, а упрощённый вариант:
линейные слоты-хранилища + необучаемая запись + обучаемое извлечение в
логпроб-пространство. План восстановим: MLP-слоты (3.1) + обученная η через
классификатор (3.2) возвращают ключевые элементы плана без риска потерять
рабочий результат. Полный bilevel (3.3) — эксперимент с тёплого старта.

## 9. Архитектура MLP-памяти и решения проблем (продумано, 2026-08-03)

### 9.1 Изучение кода (факты, на которых строится решение)
- MemoryMLP (titans-pytorch/memory_models.py): dims = (dim, dim·expansion, dim),
  GELU между слоями, БЕЗ bias, xavier_uniform; обёртка ResidualNorm:
  `M(x) = LayerNorm(MLP(x)) + x` — residual спасает от схлопывания к нулю.
- TTT-LM (ttt.py): внутренние шаги — АРИФМЕТИКА без detach
  (`W1 = W1 − lr·ΔW1`), граф через ВСЕ шаги (gradient checkpointing по seq),
  lr обучаемый. Это и есть их bilevel.
- ПРИЧИНА НАШЕГО ПРОВАЛА bilevel: я обрывал граф клонами (detach + create_graph
  только на последних чанках) — градиенты в θ₀ не шли. У TTT-LM обрывов нет.

### 9.2 Итоговая архитектура (MLP-память)
```
ПАМЯТЬ: N_SLOTS=32 слота × MemoryMLP(896→H→896, GELU, без bias, xavier) + residual-обёртка

ЗАПИСЬ (механика, Titans-правило, на автономных клонах):
  для чанка (CHUNK=16 токенов), ITERS=2..4:
    s = argmax(h_t @ route_keys)                     # маршрутизация записи
    θ_s ← θ_s·(1−γ) − η·∇||M_s(h_t)−h_t||²          # нормированные шаги
  (η=0.3, γ=0.01; 3.2: η_t = classifier_know_notknow(h_t) — novelty гейтит θ_t)

ЧТЕНИЕ (обучаемое извлечение):
  w = softmax(q @ W_route)                           # веса слотов (обучаемые)
  mix = g·W_out(Σ_i w_i·(M_i(q; θ_work) − M_i(q; θ₀)))   # [6] сдвиг логпробов
  final_logits[кандидаты] = logits_noctx[кандидаты] + mix

ОБУЧЕНИЕ:
  Фаза 1 (alignment, 15 эпох): M(h)≈h на hidden Qwen — θ₀ учатся (слоты говорят
    на языке Qwen; residual: даже при схлопывании отклик = h — не ноль)
  Фаза 2 (дистилляция, 20-35 эпох): θ₀ ЗАМОРОЖЕНЫ; обучаются W_route, W_out, g
    loss = CE(final_logits, правильный) + 0.5·MSE(mix, target6)
```

### 9.3 Как решаются проблемы (явно)

| Проблема | Решение |
|---|---|
| 1. Bilevel не сходился (7 прогонов, mix≈0) | Два уровня: (а) СЕЙЧАС — запись необучаемая механика (клоны), извлечение обучаемое — работает 85%; (б) 3.3 — полный граф TTT-стиля БЕЗ detach, create_graph на всех чанках, gradient checkpointing, обучаемый lr — как в ttt.py |
| 2. MLP схлопывался к нулю | (а) ResidualNorm-обёртка: M(x)=MLP(x)+x — при схлопывании отклик=h (identity), не ноль; (б) GELU (не tanh — нет насыщения); (в) без bias + xavier_uniform (как Titans); (г) нормированные шаги записи — веса не раздуваются; (д) alignment-предобучение — старт не со случайных весов |
| 3. Нелинейность не запоминает за 1 шаг | ITERS=2..4 итерации записи на чанк (smoke: 16 итераций дали −16%) |
| 4. Точность подмешивания в hidden недостижима (Δ~150, norm давит) | Выход памяти = сдвиг логпробов кандидатов (6 чисел) — прямая метрика; MLP даёт ёмкость хранения, W_out извлекает сдвиг |
| 5. Стоимость (896→3584→896 × 32 слота = 205M параметров) | H конфигурируем: 256 (быстрый прогон) → 896 → 3584 (по плану); сокращённый прогон: N_TRAIN=120, ITERS=2, EPOCHS=20 |

### 9.4 Реализация (правки кода)
1. SlotMLP: Linear(896,H,bias=False)→GELU→Linear(H,896,bias=False), xavier_uniform,
   residual-обёртка: forward = mlp(x) + x.
2. write_work: functional_call с параметрами (W1,W2), шаги на оба, ITERS.
3. read_theta/read_diff: functional_call (уже обобщено).
4. Конфиг: H_SLOT=256, ITERS=2, N_TRAIN=120, EPOCHS=20 — быстрый прогон.
5. Метрики: val_acc дистилляции ≥ 0.88, межсессионный ≥ 34/40.

### 9.5 Порядок
1. Правки кода (этот раздел) → быстрый прогон (~1 ч) → eval_cross_session.
2. Если ≥34/40 — масштабировать (H, ITERS, эпохи) и 3.2 (η через классификатор).
3. 3.3 — полный bilevel TTT-стиля с тёплого старта (эксперимент).
