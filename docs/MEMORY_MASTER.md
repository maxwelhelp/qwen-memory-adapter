## 1. Карта

Всё, что накопилось, распадается на **три направления**, которые ЧАСТО путаются между
собой, но решают разные задачи:

| Направление | Вопрос, на который отвечает | Что меняется | Персистентность |
|---|---|---|---|
| **A. MLP-память (веса=контекст)** | Как заменить KV-кэш на маленькую сеть, чья ВЕСА и есть запомненный контекст? | Веса отдельной маленькой сети (память) | Между СЕССИЯМИ (кэш Qwen выброшен — память помнит) |
| **B. Скоринг KV-кэша (эвикция)** | Какие токены оставить/выбросить из KV-кэша, чтобы не терять важное при сжатии? | Набор ключей/значений В КЭШЕ Qwen (сам кэш) | В рамках ОДНОЙ сессии (длинный контекст) |
| **C. Общая россыпь (fast weights, тернарная память, retrieval, soft-tokens)** | Как вообще прикрутить обучаемую память к замороженной LLM — с нуля, полный обзор вариантов | Разное (зависит от варианта) | Разное |

Qwen (2.5-0.5B-Instruct) во всех направлениях **заморожена** — учится только
внешний/навесной модуль. Это сквозной принцип всего проекта.

Направление A довели до РАБОТАЮЩЕГО результата (85% межсессионный тест).
Направление B довели до промежуточного результата (80% vs 20% у H2O).
Направление C — банк идей, ни одна ветка не начата экспериментально (кроме того,
что уже пересекается с A и B).

## 2. Направление A — MLP-память как модуль

*Источники: `ARCHITECTURE.md`, `memory_layer_v2.md`, `REPORT_MEMORY_MLP.md`, `RESULTS.md`
(разделы «шаг 2-4», «MLP-слоты»), `titans_qwen.md`, `titans_qwen2.md`.*

### 2.1 Идея одним абзацем

Рядом с замороженной Qwen2.5-0.5B-Instruct живёт маленькая сеть-память. Контекст
записывается в её ВЕСА градиентными шагами (Titans-стиль) — не в KV-кэш, не в текст.
При вопросе память читается и подмешивается в ответ. Главный сценарий — **персистентность
между сессиями**: кэш Qwen выбрасывается, веса памяти сохраняются на диск — память помнит
то, что Qwen уже забыла.

### 2.2 Итоговая архитектура (та, что реально работает, 85%)

```
                    Qwen (ЗАМОРОЖЕНА)
                              │
        hidden-состояния контекста (вход последнего слоя, 896)
                              │
        ┌─────────────────────▼──────────────────────┐
        │  ПАМЯТЬ                                      │
        │                                              │
        │  N_SLOTS=32 слота × SlotMLP                   │
        │    Linear(896→H)→GELU→Linear(H→896),          │
        │    без bias, xavier_uniform (H: 256/512/896)  │
        │                                              │
        │  ЗАПИСЬ (необучаемая механика, на инференсе): │
        │    маршрут: s = argmax(h · route_keys)        │
        │    шаг:  θ_s ← θ_s(1−γ) − η_t·∇||M(h)−h||²    │
        │    нормированный (ĝ=g/||g||), чанками(CHUNK=16)│
        │    η_t = σ(W_eta(h_t)) — «как сильно писать»  │
        │    (учитель: секрет=1, мусор=0.1)              │
        │                                              │
        │  ЧТЕНИЕ (обучаемое извлечение):               │
        │    веса слотов: w = softmax(q · W_route)      │
        │    mix = g·W_out(Σ_i w_i·(M_i(q;запись)−      │
        │                              M_i(q;θ₀)))      │
        │    mix — 6 чисел = сдвиг логпробов кандидатов │
        └─────────────────────┬────────────────────────┘
                              │ mix
                              ▼
   final_logits[кандидаты] = logits_noctx[кандидаты] + mix
```

**Инференс (два сеанса):**
```
Сессия 1:  контекст → write_work (градиентные шаги по клонам слотов)
           веса памяти (memory_distill.pt) сохраняются на диск
           кэш Qwen выброшен

Сессия 2:  только вопрос → forward Qwen без контекста
           q = hidden последней позиции
           mix = g·W_out(Σ w_i·(M_i(q;запись) − M_i(q;θ₀)))
           pred = argmax(логпробы кандидатов без контекста + mix)
```

### 2.3 Фазы обучения

| Фаза | Что учится | Лосс | Цель |
|---|---|---|---|
| 1. Alignment | слоты θ₀ | `‖M(h)−h‖²` на скрытых состояниях Qwen | память «говорит на языке Qwen» |
| 1.5. η-голова | W_eta | BCE(σ(W_eta(h)), mask_secret) | секрет пишем сильно, мусор — слабо |
| 2. Дистилляция | W_route, W_out, g (слоты заморожены) | CE(кандидаты) + 0.5·MSE(mix, target6) | память отдаёт то, что нужно для ответа |

target6 = логпробы кандидатов с контекстом − без контекста.

### 2.4 Пять ключевых архитектурных решений (почему именно так)

1. **Запись необучаемая, чтение обучаемое.** Bilevel-градиенты через запись не доходят
   (клоны весов обрывают граф, mix≈0 — 7 неудачных прогонов). Разделение труда: запись —
   механика хранения (нормированные шаги самовосстановления), чтение — обучаемое
   извлечение.
2. **Alignment обязателен.** Случайное пространство слотов не связано с пространством
   Qwen — без alignment дистилляция учит и семантику, и механику одновременно и не
   сходится.
3. **Выход в пространство логпробов кандидатов** (6 чисел), а не вектор в hidden:
   Δ выхода ~150 при ‖h‖~15 — операция `norm()` давила и сигнал, и градиенты в ~150 раз.
   Сдвиг логпробов — прямая, недвусмысленная метрика.
4. **MLP-слоты без residual-обёртки.** `MLP(x)+x` (как в Titans) сводит запись к нулю
   (‖MLP(h)‖²→0) и обнуляет разность откликов → mix≈0. (В Titans residual нужен, потому
   что там память — слой модели; у нас mix = разность откликов, и residual его убивает.)
5. **Нормированные шаги записи** (ĝ = g/‖g‖) — веса не взрываются (взрывы были при
   ETA=0.5 на длинных контекстах).

### 2.5 Сигнал новизны (что писать сильно, а что — слабо)

```
Δlogprob(токен) = logprob(токен | с контекстом) − logprob(токен | без контекста)
```
- Δ большая → знание только из контекста (новое для Qwen) → высокий η;
- Δ ≈ 0 → Qwen знала и без контекста → слабая запись, не тратим ёмкость.

Три фильтра «не всё, а как надо» (из `memory_layer_v2.md`, п.4c):
1. Новизна для Qwen (Δlogprob / классификатор know-not-know) — неизвестное детально,
   известное — не тратим;
2. Важность (головы: внимание / удивление / аннотация) — что пригодится для ответов;
3. Ёмкость ограничена + decay (γ) — старое/неважное вытесняется.

### 2.6 Двухуровневая память L_fast/L_slow (титановское развитие, не реализовано)

Идея из `titans_qwen2.md`: два экземпляра ОДНОЙ И ТОЙ ЖЕ архитектуры памяти с разными
таймскейлами вместо одного порога novelty:

```
L_fast  (chunk ≈ 1-8 токенов):  быстро пишет, быстро забывает, живёт в рамках сессии
L_slow  (chunk ≈ 256+ токенов): пишет редко, только на устойчивую новую информацию,
                                  персистентна между сессиями
```

L_slow пишет только если novelty стабильно высокий несколько чанков подряд (не разовый
всплеск) — фильтрует шум от реального «факта, который стоит помнить надолго». Чтение —
оба уровня отдают top-k слотов, конкатенируются как 2-4 доп. soft-токена, вставляются в
последние 4-6 слоёв attention; отдельный гейт «какой уровень важнее» не нужен —
замороженное attention само разберётся (как в обычном MAC).

Из результатов синтетического теста памяти (`RESULTS.md`, шаг 2): «различие γ работает,
НО L_slow копит шум» → вывод: разделять L_fast/L_slow нужно по ПОРОГУ/ЧАСТОТЕ записи,
не только по величине γ.

### 2.7 Persistent tokens-якоря (Titans, не реализовано)

Несколько (например, 4) всегда присутствующих обучаемых токенов, не зависящих от
retrieval, прикреплённых рядом с памятью. Роль — стабилизировать вставку в attention
(«якорь», к которому attention может привыкнуть, вместо нового распределения активаций
каждый раз). Дёшево: пара тысяч параметров, обучаются вместе с проекциями офлайн.

### 2.8 Что явно НЕ входит в направление A (жёсткая рамка)

- НЕ кэш, НЕ скоринг, НЕ эвикция, НЕ база, НЕ переполнение контекста (это направление B).
- Внимание Qwen не трогается, Qwen заморожена, end-to-end обучения — нет.
- Замена MLP-слоёв Qwen — тоже нет (память живёт сбоку, как в MAC-схеме).

## 3. Направление B — обучаемый скоринг KV-кэша (эвикция)

*Источники: `RESULTS.md` (верхняя часть), `kv_mechanisms.md`, `annotator_teacher.md`,
`tiered_memory_mlp.md`.*

### 3.1 Задача

В KV-кэше нужно решить, какие токены оставить, какие выбросить, не теряя то, что
понадобится для будущего вопроса. Главная проблема существующих методов (H2O-стиль,
по накопленной attention-массе) — **dormant-токены**: токены с нулевым текущим вниманием
(например, спящий пароль в мусорном контексте), которые выбрасываются в 100% случаев,
хотя они критичны для будущего вопроса.

### 3.2 Итоговая (протестированная) схема

Одна сеть (backbone 896→256), две головы:
- голова A = attention-масса (учитель — накопленное внимание, H2O-сигнал);
- голова B = удивление z-score (учитель — EpiKV-стиль, L2-изменение hidden между
  decode-шагами, z-score по скользящему окну).

```
score = score_attn + β·score_surp
evict = score_t < τ,  сохраняя sliding window 64 + union top-K/3 со страховкой вниманием
```

Эвикция — additive 3D-маска (−inf для выброшенных ключей) на ВСЕХ слоях; сам softmax/QKV
внимания не меняется.

### 3.3 Результаты (dormant-задача, «Пароль: X7K9Q2» в мусоре, budget 10%)

| Режим | Ответ верный | Спящий пароль сохранён |
|---|---|---|
| dense (полный контекст) | 20/20 (100%) | 20/20 (100%) |
| attn_mass (H2O-стиль) | 4/20 (20%) | 0/20 (0%) |
| ours β=0.0 (attn-голова + страховка) | 16/20 (80%) | 13/20 (65%) |
| ours β=0.5 | 16/20 (80%) | 13/20 (65%) |
| ours β=1.0 (чистое удивление, без страховки) | 4/20 (20%) | 13/20 (65%) |

Выводы: dormant-проблема воспроизведена (H2O = 0% на спящий пароль, согласуется с
Transactional Attention, 2604.11288). Union со страховкой attention-массой обязателен —
без него удивление само по себе выбрасывает маркеры-подсказки («Пароль:»). Итог:
обученный двухголовый скоринг + union бьёт H2O-стиль в 4 раза (80% vs 20%) при том же
бюджете 10%.

### 3.4 Третья голова — аннотатор с будущим вопросом (продумано, тест-взгляд пройден)

Идея (`annotator_teacher.md`): второй проход модели-аннотатора получает **контекст +
будущий вопрос** и JSON'ом размечает важные/неважные фрагменты. Ключевое отличие от
эвикции на инференсе — датасет строится ОФЛАЙН, вопрос уже известен, поэтому аннотации
не слепые.

```
для каждого примера:
    промпт аннотатора: «Контекст: {ctx}\nВопрос: {q}\nВерни JSON:
      {"important": [...], "unimportant": [...]}»
    → маппинг фрагментов на токены (по декодированному тексту)
    → target_annot_t: 1 = important, 0 = unimportant, нейтральные — пропуск
    (опц.) контрафактическая валидация: убрать important → ответ должен измениться;
           убрать unimportant → ответ не должен измениться
```

Встраивается как третья голова к той же архитектуре:

```
hidden_t ──► backbone ──► голова A: score_attn  (учитель: attention-масса)
                  │      ├─► голова B: score_surp (учитель: удивление z-score)
                  │      └─► голова C: score_annot (учитель: аннотация с вопросом)
                  ▼
         score = score_attn + β·score_surp + γ·score_annot
```

На инференсе аннотатор НЕ вызывается — третья голова уже выучила, «что модель считает
важным для будущих вопросов», из офлайн-датасета. γ настраивается на валидации, как β.

**Результат теста-взгляда (2026-08-03, `annotator_test.py`, Qwen2.5-0.5B-Instruct):**

| Задача | Метки | Результат |
|---|---|---|
| Dormant (спящий пароль, вопрос «какой пароль?») | пароль в important | **10/10 (100%)** |
| Правила (условие в тексте, вопрос «что делать, если X?») | условие в important | **10/10 (100%)** |

Аннотатор с будущим вопросом помечает спящие токены (которые attention-масса не видит
никогда) в 100% случаев. Построен первый кусок датасета-учителя, где сеть сама (вторым
проходом, видя будущий вопрос) написала, что в контексте важно, а что нет.

Связь с офлайн/онлайн-версиями критики-буста: офлайн (описано выше) — дёшево на
инференсе (0 доп. проходов); онлайн (критик на инференсе, score += boost·annot для
конкретного контекста) — 2× дороже, но адаптивно. Порядок: сначала офлайн, онлайн-буст —
только если офлайн уже даёт сигнал.

### 3.5 Трёхуровневая память: KV-кэш + внешняя база + retrieval (`tiered_memory_mlp.md`)

Развитие скоринга — не выбрасывать токены совсем, а выгружать в БД:

```
УРОВЕНЬ 1 — KV-кэш (горячий, GPU): топ-скоринг токены (~10%)
      │  выгрузка (НЕ выбрасывание!)
      ▼
УРОВЕНЬ 2 — Внешняя база (векторная, диск/RAM): остальное + что не влезло в контекст
      │  retrieval, когда «не нашлось в кэше»
      ▼
      → найденные KV возвращаются во внимание (как обычные ключи)
```

MLP-скоринг работает МАРШРУТИЗАТОРОМ между ярусами: (1) что оставить в кэше;
(2) что выгрузить в базу, а не удалить — решает по скору (высокий скор, но не влез →
база); (3) что искать в базе — формирует retrieval-запрос (удивление/аннотация как
сигнал запроса). Страховка: спящий пароль, не попавший в кэш, не теряется — он в базе,
retrieval достаёт его при вопросе.

Замедление инференса: уровень 1 бесплатен (одна MLP-прогонка); уровень 2 добавляет
+10–100 мс на запрос (FAISS/ANNS), но включается только когда «не нашлось в кэше» —
оверхед почти нулевой; на коротких контекстах база вообще не нужна (порог по длине).

Кто ещё так делает (для контекста, не изобретаем велосипед):

| Система | Админ/маршрутизатор |
|---|---|
| RetrievalAttention | обученные адаптеры-предсказатели страниц (ANNS) |
| InfLLM | эвристика важности блоков |
| kv2state (tiered cache) | мульти-сигнальный скоринг: attention, recency, cross-head variance, distinctiveness |
| Memorizing Transformers | kNN-поиск без маршрутизации |
| PQ-Cache / MagicPIG | MIPS/LSH retrieval без обучения |
| **Наш** | обученный скоринг: attention + удивление + аннотация (семантика) |

### 3.6 Перенос скоринга на другие модели — честный ответ

- Переходник размерности (Linear(d_other→d_896)) технически работает, но
  hidden-распределения разных моделей не совпадают → качество падает; годится только как
  стартовая точка + дообучение.
- Обучение под каждую модель отдельно — так делают все (KVzap: свои веса на каждую
  модель), стоит 30-60 мин (автодатасет + быстрый тренинг) — не сильная навеска.
- Инвариантные фичи (z-score удивления, относительные ранги attention-массы, аннотации) —
  частичный перенос, но точность требует лёгкого дообучения на новой модели.
- Итог: полный drop-in без переобучения невозможен; лёгкое дообучение — стандарт.

## 4. Направление C — общая россыпь архитектурных идей

*Источники: `01-memory-architecture-kv-fastweights.md`, `04-online-mlp-memory-qwen.md`,
`titans_qwen.md` (первая половина, до разбора дыр).* Это банк идей ДО начала конкретных
экспериментов A и B — многое из него уже частично вошло в A/B, но есть и нетронутые ветки.

### 4.1 Три исходных компонента (самая первая формулировка идеи)

1. **«Подсказывающее» внимание** — маленькая голова/подсеть, генерирующая не токены
   ответа, а мета-инструкцию для следующего шага агента (близко к gating-сети MoE, но
   выход — не «какой эксперт», а «какая подсказка»). Риск не архитектурный, а обучающий:
   нужен сигнал «что такое хорошая подсказка» (RL с reward-моделью либо дистилляция).
2. **Детектор ошибок/раздражения** («если после ~20 попыток получилось — сохранить как
   скилл») — классификатор на скрытых состояниях. Сохранение «как скилл» — это
   episodic/skill memory (уже реализовано в Voyager, Generative Agents, memory-stream
   подходах): скилл — переиспользуемый артефакт (промпт/код), достаётся через retrieval,
   не встраивается в веса.
3. **JSON-лог об ошибках/успехах** — структурированный лог, самая дешёвая часть, отдельная
   маленькая модель-классификатор выдаёт сводку на шаге или в конце сессии.

Ключевое архитектурное решение той стадии: писать в веса на лету (Titans-стиль) — дорого
и рискованно (catastrophic forgetting, дрейф); писать во внешнюю память (вектор/граф БД) и
доставать через RAG — дёшево и предсказуемо. Рекомендованное разделение:

- **Внутри модели** — только лёгкие головы генерации подсказок/классификации на уровне
  текущего диалога (живёт только в контексте сессии).
- **Снаружи модели** — персистентная память (skill library, история ошибок) с retrieval,
  куда пишет «судья»-классификатор после сессии или каждые N шагов.

### 4.2 Веса как key-value память — теоретическая база

Geva et al., «Transformer FF Layers Are Key-Value Memories» (2020): FFN-слой трансформера
математически есть key-value память — первая матрица — ключи, вторая — значения,
активация между ними — «насколько текущий вектор похож на записанный ключ». Это основа
для всей идеи «писать факты прямо в веса».

**Fast weights (Schmidhuber, 90-е):** одна сеть генерирует не выход, а ИЗМЕНЕНИЯ весов
другой сети в реальном времени — «запись» информации прямо в матрицу как в память. Titans
— современный потомок этой идеи. Linear attention можно переформулировать как rank-1
обновление матрицы памяти на каждом токене — внимание и «запись в веса» в некоторых
формулировках одно и то же с разных сторон.

### 4.3 Три отдельные (но совместимые) идеи и «нетронутая щель»

1. Внешняя векторная память (retrieval) — дёшево, но неглубоко интегрирована с весами.
2. Fast weights/hypernetwork запись прямо в веса — глубоко интегрировано, но дорого и
   рискованно (забывание).
3. Тернарные/квантованные веса (BitNet b1.58, 2024: веса буквально {-1,0,1}, обучение
   через straight-through estimator, инференс дешевле в разы) — дёшево по инференсу, но
   пока не связано с 1 и 2.

**Не реализованная, но не занятая ниша**: тернарная/дискретная fast-weight память,
адресуемая ключом, где «запись» — не градиентный шаг, а дискретная операция (+1/-1/0 в
ячейку по хэшу ключа), как ассоциативная память типа Hopfield-сети, но тернарная. Плюсы:
дешёвая запись, дешёвое хранение (1.58 бита/параметр), потенциальная устойчивость к
забыванию (дискретные операции легче версионировать, чем непрерывные градиенты).

Архитектура целиком:
```
[Основная LLM, заморожена] → h_t →
[Детектор (мини-attention, можно тернарный)] — уверенность/ошибка/успех/«запомни»
        │
        ├── «не пиши» → продолжаем как обычно
        └── «пиши» →
                [Проектор h_t → k_t] → [Хэш k_t → адрес ячейки в тернарной памяти M]
                → [Запись: M[адрес] = ±1/0]  (дискретная операция, не градиент)

При генерации:
h_t → [Проектор → k_t] → [Хэш → чтение из M] → [Проектор обратно в latent] →
   добавляется в residual stream / подмешивается в attention
```
Детектор и проекторы обучаются backprop'ом как обычно (LoRA-подобная схема поверх
замороженной модели). Матрица памяти M — Hebbian-подобное правило («усиливай связь при
совпадении сигнала с ожиданием, ослабляй при расхождении»), backprop через дискретные
операции напрямую не работает — это главный открытый вопрос ветки.

### 4.4 Упрощённая (реализуемая) версия: LoRA-память вместо дискретного хэша

```
h_t → [Проекция P: h_t → e_t] → [LoRA-адаптер поверх памяти] ← сюда идёт градиент
    → запись/обновление вектора памяти
```

«Запись» — обычный градиентный шаг, но ограниченный низкоранговой матрицей (LoRA), а не
полным весом — снижает и стоимость, и риск catastrophic forgetting.

Родственные направления: **Test-Time Training (TTT-layers, 2024)** — слой, делающий
мини-градиентный шаг по своим весам во время инференса на основе текущего контекста,
встроен внутрь архитектуры (не адаптер сбоку); **Transformer² (Sakana AI, 2025)** —
LoRA-подобная дельта весов адаптируется на лету под задачу; **Larimar (IBM, 2024)** —
внешняя память с эпизодами, запись/чтение через дифференцируемые операции.

Два вопроса, которые нужно продумать заранее:

1. **Какой лосс двигает запись?** Loss = «предскажи следующий токен лучше» → обычный
   continual learning со всеми рисками переобучения/забывания. Loss = «минимизируй
   расстояние между e_t и уже записанным похожим вектором» (contrastive/metric learning)
   → организация памяти, а не давление на выходы модели — **рекомендованный вариант**.
2. **Скорость записи vs чтения — разделять архитектурно.** Чтение — быстрый forward pass
   с cosine similarity/attention над векторами памяти, без градиента. Запись — реже, по
   событию (детектор решил «важно»), можно асинхронно/в фоне после ответа.

Забывание всё равно есть — LoRA-дельта тоже непрерывные веса, продолжая писать в неё
градиентами, старые записи постепенно стираются (классическая проблема continual
learning). Пути решения: несколько независимых низкоранговых блоков под разные «области»
фактов с routing (MoE-стиль над памятью); либо периодическая заморозка старых LoRA-блоков
и создание новых (версионирование).

### 4.5 Выравнивание пространства памяти с основной моделью (дистилляция)

Если пространство памяти обучать с нуля независимо от Qwen — оно не связано с тем, как
Qwen «понимает» слова, проектору приходится учить семантику заново по парам
(h_t, событие записи) — долго и шумно. Дистилляция эмбеддингов решает это заранее:
пространство памяти «говорит на том же языке» с самого начала, проектор становится почти
identity-функцией. Соответствует model stitching / representation alignment исследованиям
(независимо обученные сети часто приходят к похожим latent-пространствам с точностью до
линейного преобразования — **Platonic Representation Hypothesis, 2024**).

Два варианта дистилляции:
- **А. На уровне эмбеддингов токенов** — MSE/cosine на статичной семантике слов. Дёшево
  и быстро, но не контекстно.
- **Б. На уровне контекстных скрытых состояний** — приближает h_t в контексте. Ближе к
  реальной задаче, но дороже (нужны оба forward pass на большом числе контекстов).

Рекомендация: начать с А, расширять до Б при необходимости. Это НЕ полная дистилляция
знаний (Hinton et al.) — там студент воспроизводит весь выход учителя; здесь нужно только
согласовать ПРОСТРАНСТВО векторов:

```python
# один раз, офлайн
for x in anchor_corpus:
    h_qwen = qwen.forward_to_layer(x, L).detach()
    h_mem  = memory_encoder(x)
    loss = 1 - cosine_similarity(project(h_mem), h_qwen)   # или MSE
    loss.backward()   # обучается только memory_encoder / проектор
```

Дрейф пространства во времени: если Qwen потом дообучат, латентное пространство сместится
— память «устареет». Решение — не дистиллировать раз и навсегда, а держать лёгкий
continual-alignment лосс (раз в N записей — маленький шаг дистилляции).

Дистиллированная мини-сеть — НЕ база данных: она учит функцию (вход → вектор в
согласованном пространстве), генерализует на невиданные входы, а не хранит построчно, как
таблица. Итоговая двухслойная схема:

```
Слой 1 (дистиллированный энкодер) — «геометрия языка», статичный, почти не меняется
        ▼
Слой 2 (LoRA-память / явная таблица) — растёт и наполняется конкретными фактами со временем
```
Слой 1 — «словарь смыслов» (обучается редко), Слой 2 — «дневник событий» (растёт
постоянно, ведёт себя как база данных). Если писать новые факты прямо в веса Слоя 1 —
риск размыть выровненную геометрию (пришлось бы передистиллировать).

### 4.6 Суперпозиция и Sparse Autoencoder (SAE) для ключей памяти

`nn.Embedding` архитектурно уже таблица (индекс токена → строка-вектор) — «векторная БД»
по построению, ещё до разговоров про суперпозицию. Anthropic, «Toy Models of
Superposition» (2022), затем «Towards/Scaling Monosemanticity»: размерность эмбеддинга
намного меньше числа реальных концептов, признаки размещаются по почти ортогональным
направлениям (лемма Джонсона-Линденштрауса), платится интерференцией редких признаков.

**SAE (sparse autoencoder / dictionary learning):** плотный полисемантичный вектор →
автоэнкодер с избыточной размерностью + разреженность → набор монозначных направлений,
каждое ближе к одному интерпретируемому понятию. Полезно для ключей памяти: похожесть по
ключу после SAE реально означает смысловую похожесть (а не совпадение из-за интерференции),
плюс естественная интерпретируемость — видно, какой признак вызвал запись в память
(полезно для отладки детектора «что важно запомнить»).

### 4.7 Относительные представления и передача латентного вектора между сетями

**Model stitching / relative representations** (Moschella et al., 2023): перевод внутренних
представлений в пространство ОТНОСИТЕЛЬНЫХ расстояний (не абсолютных координат) позволяет
«сшивать» куски одной сети к другой почти без потерь. **Vec2Vec / unsupervised embedding
translation (2024)**: перевод эмбеддингов между пространствами вообще без пар примеров,
просто выравниванием геометрической структуры. **Coconut / Chain of Continuous Thought
(Meta, 2024)**: модель передаёт hidden state себе на следующий шаг напрямую, без перевода
в текст — эффективнее пошагового CoT (токен = узкое горлышко на несколько бит, вектор
несёт на порядки больше). Родственно soft prompts / prompt tuning.

Подвох: когда векторы передаются напрямую (не через текст), теряется интерпретируемость —
нельзя проверить, что реально передалось, есть риск дрейфа смысла между несогласованными
пространствами; в multi-agent системах это обсуждается как риск **cross-model
steganography**. Практический вывод: если векторы идут напрямую между «основной моделью»
и «памятью» — стоит сознательно закладывать возможность декодировать вектор памяти обратно
в текст для отладки, даже если в проде не используется.

Алгоритм относительных представлений (конкретно, «нулевое обучение»-fallback):
```
1. Выбрать якоря (100-1000 общих примеров текста для обеих сетей).
2. Эмбеддинги якорей в каждой сети: a_i (сеть А), b_i (сеть Б) — разные пространства.
3. Новый вектор x → относительное представление:
     r_A(x) = [cos_sim(embed_A(x), a_1), ..., cos_sim(embed_A(x), a_N)]
     r_Б(x) = [cos_sim(embed_Б(x), b_1), ..., cos_sim(embed_Б(x), b_N)]
4. Если якоря — одни и те же смысловые точки, r_A(x) ≈ r_Б(x), даже если исходные
   пространства несравнимы (разная размерность/поворот/масштаб).
```
Цена: O(N) скалярных произведений на вектор — дёшево, но грубее обучаемого проектора.
Практический вывод: комбинировать — относительные представления как быстрый baseline без
обучения (особенно на старте, пока нет данных для проектора), LoRA-проектор с градиентом —
как точная дообучаемая надстройка, когда накопится достаточно пар примеров.

### 4.8 Онлайн-MLP-память: детальный дизайн (наиболее проработанная ветка C)

*Из `04-online-mlp-memory-qwen.md` — отдельный, более развёрнутый вариант направления A,
с упором на разреженность и explicit gate.*

```
prompt ──► Qwen (frozen) ──► h_L (слой L) ──► gate(h_L, uncertainty) ──┐
                                                                         ▼
                                                  ┌───────────────────────────┐
                                                  │   Memory MLP (обучаемая)   │
                                                  │  - читает h_L              │
                                                  │  - выдаёт delta-вектор     │
                                                  │  - обновляется online      │
                                                  └───────────────────────────┘
                                                                 │
                                                  gate * delta ──┘
                                                                 ▼
                                    h_L' = h_L + gate * delta  (residual)
                                                                 ▼
                                            дальше по слоям Qwen как обычно
```

Три механизма, которые важно не путать:

| Механизм | Что меняется | Насколько постоянно |
|---|---|---|
| Инъекция в residual (`h_L' = h_L + gate·delta`) | Ничего в весах Qwen, добавка живёт только в рамках forward pass | Эфемерно |
| Обучение Memory MLP (online) | Веса памяти, не Qwen | Постоянно, накопительно |
| Консолидация в Qwen (опц.) | Веса самой Qwen (ROME-стиль patch) | Постоянно, но отдельный рискованный шаг |

**Компонент A — дистилляция embedding-пространства** (см. также §4.5): Procrustes
(закрытое SVD-решение без обучения, если память архитектурно близка к Qwen) или
дистилляция (если память — независимая маленькая сеть).

**Компонент B — активные нейроны** (нужен ли отдельный forward?): нет, переиспользуется
уже посчитанная арифметика —
```python
h = qwen.hidden_state_at_layer(x, L)
a = silu(Wg_mem @ h) * (Wu_mem @ h)                # rank-1 атом на нейрон памяти
active_mask = topk_by_abs(a, k) | (|a| > percentile_thresh)
```
`active_mask` используется и на чтение (какие нейроны реально участвуют, sparse forward),
и на запись (какие строки/столбцы весов памяти вообще разрешено трогать на этом шаге).

**Компонент C — сигнал surprise** (что писать в память): не обучать на всём подряд.

| Сигнал | Как считать | Стоимость |
|---|---|---|
| Loss/perplexity Qwen на текущем токене | `-log p_qwen(x_true|context)` | бесплатно |
| Энтропия распределения Qwen | `entropy(softmax(logits))` | бесплатно |
| Semantic entropy (Kuhn et al., 2023) | N сэмплов + кластеризация по смыслу | дороже, но точнее |
| Разрыв logit lens между средним и последним слоем | `KL(p_mid‖p_final)` | средне |
| Градиент лосса памяти (Titans-стиль) | `‖∇_θ_mem loss‖` при записи | считается заодно с backward |

Практичный минимум для старта: entropy + perplexity на true-токене (обе бесплатны). Если
surprise низкий — не пишем, экономим ёмкость.

**Правило записи (delta-rule + forgetting), ограниченное на `active_mask`:**
```python
S = active_mask
target = teacher_signal(x)          # true-токен / выход сильной модели / causal-tracing атлас
lr_t   = eta * surprise_t
decay  = lambda_forget
W_mem[S] = (1 - decay) * W_mem[S] + lr_t * outer(h[S], target)
```
Forgetting двух типов: (1) мягкий decay каждый шаг — тянет редко используемые веса к нулю;
(2) жёсткая чистка — счётчик использования, если нейрон не входил в active_mask N шагов
подряд, слот сбрасывается/переиспользуется (реюз, конечная ёмкость не растёт бесконечно).

**Структурная разреженная LoRA** вместо dense W_mem:
```python
# B:[D,r], A:[r,D] — обновляются только строки/столбцы в active_mask S
B[S, :] += lr_t * surprise_t * grad_B[S, :]
A[:, S] += lr_t * surprise_t * grad_A[:, S]
```
Плюсы: меньше параметров трогается за шаг (меньше интерференции фактов), дешевле по
памяти/градиентам, естественно ограничивает «ёмкость на факт» (низкий ранг → старые дельты
вытесняются decay'ем сами).

**Инъекция вывода — вектор в hidden, а не текст:**

| | Vector injection (residual) | Text injection (RAG-стиль) |
|---|---|---|
| Точность | прямая, на уровне направления в пространстве | ограничена вербализуемостью |
| Стоимость | одна арифметическая операция | съедает токены контекста, доп. forward |
| Обратимость | легко тестировать (rel_err до/после) | труднее измерить точечный эффект |
| Как fallback | — | грубее, но надёжнее и проще дебажить |

`h_L' = h_L + gate*delta`, слой L — там же, где обычно ищут factual recall circuits
(средние слои, ROME/Dai et al.), не обязательно последний.

**Gate — когда инжектировать (не один источник, комбинация двух):**
```
gate = f( uncertainty(h_L, prompt) , similarity(query, memory_keys) )
```
1. От состояния Qwen (uncertainty: entropy/logit-lens-gap) — инжектировать только когда
   Qwen сомневается, иначе можно испортить то, что и так работало.
2. От релевантности памяти (cosine similarity h_L / relative representation с ключами
   памяти) — если ничего похожего в памяти нет, gate=0, инъекция бессмысленна.
3. Не от сырого промпта напрямую — от hidden state (уже учитывает контекст на нужном
   уровне абстракции; сырой текст для gate — более шумный и дорогой сигнал).

MVP-версия без обучения:
```python
gate = 1.0 if (entropy_qwen > tau_uncertain and max_sim(h_L, mem_keys) > tau_relevant) else 0.0
# позже: gate = sigmoid(w1*entropy + w2*max_sim - b)
```
Финальная версия — маленькая gate-сеть, обучаемая на сигнале «стало ли лучше после
инъекции».

**Приоритизированный план тестирования этой ветки (от дешёвого к амбициозному):**
1. MVP — чистый retrieval без обучения памяти вообще (растущая key-value таблица,
   эвристический gate, vector injection) — проверить, что механизм gate+injection не
   ломает Qwen и вообще помогает на очевидных примерах. Самый дешёвый и диагностически
   важный шаг: если это не работает — сложная память тоже не спасёт.
2. Titans-style Memory MLP, dense update, без active-neuron маски — проверить, что
   online-обучение вообще стабильно (не расходится, не деградирует).
3. Добавить active-neuron маску — ablation против шага 2: меньше интерференция? быстрее
   сходится?
4. Structured sparse LoRA + forgetting/decay + usage-based pruning — проверка на длинном
   потоке: старое полезное знание не вымывается, шум забывается (метрика: точность на
   held-out фактах через N шагов после записи / без обращения к ним).
5. (Опционально, самый рискованный) Периодическая консолидация в саму Qwen — факты, долго
   и стабильно полезные, «выпускной экзамен» на постоянную запись в веса Qwen ROME-стилем.

## 6. Ключевые технические уроки (что не работало и почему)

### 6.1 Провал первой попытки MLP-памяти (`train_mlp_memory.py`, до текущей серии)

MLP схлопнулся к нулю. Причины: (1) запись 2 шагами на ВЕСЬ контекст — слишком мало шагов;
(2) не было η/γ-голов — веса обновлялись равномерно и затирали друг друга; (3) не было
учителя — память не знала, ЧТО отдавать (не было дистилляционного таргета);
(4) RMSNorm-насыщение tanh в архитектуре слота.

### 6.2 Bilevel-градиенты через запись не доходят (7 прогонов подряд)

Клоны весов (`.clone()`) обрывают граф автоматического дифференцирования для ранних
шагов записи → mix ≈ 0, val_acc = шанс. Фикс-обход: заморозка слотов (запись = механика,
извлечение = обучаемое) — сразу val_acc 0.85-0.88, межсессионный тест 34/40.

**Почему в самом Titans это работает** (по изучению кода `titans-pytorch/neural_memory.py`
и `ttt.py`): (а) TTT-LM делает внутренние шаги АРИФМЕТИКОЙ без detach
(`W1 = W1 − lr·ΔW1`), граф идёт через ВСЕ шаги (gradient checkpointing по seq), lr
обучаемый — обрывов графа нет вообще; (б) запись в Titans — vmap per-sample градиенты
(`per_sample_grad_fn = vmap(grad(forward_and_loss))`) внутри higher-order autograd-графа
(`torch.func`) — градиенты текут в θ₀, проекции k/v и η/γ-головы полностью, без обрезки;
(в) успех Titans обеспечивают совместное end-to-end обучение модели и памяти,
higher-order vmap-градиенты, огромный масштаб данных — ни одного из этих условий нет в
нашем случае (Qwen заморожена, маленький датасет, дистилляционный сигнал вместо языкового
лосса).

### 6.3 Residual-обёртка убивает разностную схему

`MLP(x)+x` (как в оригинальном Titans MemoryMLP) сводит запись к нулю (‖MLP(h)‖²→0), а
наша схема читает РАЗНОСТЬ откликов (`work − θ₀`) — если запись стремится к нулю, разница
тоже обнуляется, mix≈0. Для Titans residual нужен (там память — слой модели, встроенный
в forward), для нашей схемы (память сбоку, чтение = разность) — residual вреден.

### 6.4 Нелинейные слоты слабее линейных, но требуют итераций

На синтетике: линейный слот (η=0.5, 1 шаг/пару) — запись улучшает чтение на −44%
(0.336→0.189); нелинейный (η=0.1, 16 итераций) — только −16% (0.259→0.217). Вывод:
нелинейность требует ИТЕРАТИВНОЙ записи (не хватает одного шага на пару), но даже так
пока стабильно уступает линейной схеме в межсессионном тесте (34/40 линейные vs
23-24/40 MLP).

### 6.5 Точность подмешивания в hidden недостижима

Δ выхода дистилляции ~150 при типичной норме hidden ‖h‖~15 — операция нормализации
(RMSNorm/norm()) в модели давит и сигнал, и градиенты в ~150 раз, векторная дистилляция не
достигает нужной точности. Решение — выход памяти в пространство ЛОГПРОБОВ кандидатов
(6 чисел), а не вектор hidden-размерности — прямая, недвусмысленная метрика для обучения.

### 6.6 frozen_loss на токенах факта не измеряет «знает из весов» (Дыра 1, titans_qwen.md)

В one-forward режиме, если токен факта уже в контексте, teacher-forcing loss на его
позиции низкий почти всегда — модель просто копирует из контекста, даже если факта нет в
весах. Фикс: измерять энтропию/logprob НЕ на позиции самого факта, а на позиции t−1 (ДО
раскрытия факта) — модель ещё не видела факт и предсказывает следующий токен вслепую;
широкая энтропия → приходит конкретный факт → сигнал новизны без эффекта копирования. Это
и есть родное определение surprise из Titans (неожиданность входа относительно
накопленного), считается за один forward, бесплатно.

### 6.7 Один запрос M(q) на всю память = каша (Дыра 2, titans_qwen.md)

При схеме MAC (`m_t = Memory.retrieve(h_t)`) с ОДНИМ вектором на ВСЮ записанную память —
при 300 записанных фактах и вопросе про один, M(q) вернёт усреднённую кашу, замороженное
внимание её проигнорирует (и будет право). У Titans это работает, потому что память и
attention обучены совместно end-to-end; у нас Qwen заморожена. Фикс: слоты памяти (64
блока) + top-k слотов по сходству q с ключами-заголовками, либо 2-4 read-головы с разными
проекциями запроса. Без слотов retrieval — мыльный пузырь. (Это ровно то решение, которое
уже встроено в рабочую систему §2.2 — N_SLOTS=32.)

### 6.8 Синтетика (контрафакты) ≠ реальные документы (Дыра 3, titans_qwen.md)

Придуманные имена/даты дают «честное незнаю» (высокая энтропия), реальные статьи
пользователя могут давать «похожее на знакомое» — модель уверенно галлюцинирует.
Классификатор know/not-know, обученный на синтетике, будет врать на реальных документах.
Фикс: срез знаний как источник кандидатов, но ЛЕЙБЛ ставится ЭМПИРИЧЕСКИ — задаём Qwen
zero-shot вопрос про факт без контекста → ответила правильно = знает (1), не ответила = не
знает (0). Точная дата среза Qwen2.5 публично не называлась (оценки сообщества ~октябрь
2023), поэтому дата используется только для набора КАНДИДАТОВ (факты до 2022 / события
2024-2025), а не как сам лейбл — вопрос точного среза снимается целиком. По пути выяснили:
0.5B знает только 18/69 «простых» фактов (например, путает столицу России с
Санкт-Петербургом) — эмпирика оказалась честнее предположений.

## 9. Открытые направления / roadmap

Сведено из «следующих шагов» всех файлов, без дублей, примерно по приоритету.

### Направление A (MLP-память)
1. Чинить «Код»-тип в межсессионном тесте (4/10, вероятно недообучен из-за баланса типов
   в батчах) — больше данных на тип / per-type батчи.
2. 3.2 → 3.3: полный bilevel TTT-стиля (без detach, граф через все шаги, обучаемый lr) —
   возврат к «память постоянно обучается» из исходного плана, тёплый старт от текущей
   рабочей схемы.
3. L_fast/L_slow (§2.6) — связка с классификатором know/not-know (шаг 1, 92%) как η-гейт
   для L_slow.
4. Persistent tokens-якоря (§2.7).
5. Правила-задача на 1.5B (0.5B не умеет применять правила даже с контекстом — нужна
   модель посильнее для этого типа задач).

### Направление B (скоринг KV)
1. Третья голова — полный датасет аннотаций (800+ примеров: dormant + правила + тексты) →
   маппинг фрагментов на токены → target_annot → обучение → eval + контрафактическая
   валидация меток на подмножестве.
2. η/γ-головы (перенос Titans: сила держания + забывание) поверх скоринга.
3. Контрафактическое обучение (bilevel-аналог: удалил токен → ответ изменился → скор
   должен был быть выше).
4. Уровень 2 трёхуровневой памяти: выгрузка в базу вместо выбрасывания + retrieval по
   порогу (FAISS, референсы RetrievalAttention) — 2-3 дня.
5. Write-gate (не писать мусор до записи в принципе).
6. Выжимка-супер-токены (добавление, CacheNotes/Cartridges-стиль).
7. Больше данных (1.5B, 4K записей), бюджеты 5%/10%/20%, needle/LongBench-контроль.
8. Критика-буст (приоритеты из критики → boost скора важным токенам, онлайн-версия §3.4).

### Направление C (россыпь, ещё не начато экспериментально)
1. Дискретная тернарная адресуемая память (§4.3) — открытый вопрос правила записи без
   backprop.
2. MAC/MAG soft-token интеграция (titans_qwen.md) — как альтернатива текущему
   логпроб-сдвигу, потенциально даёт более богатую интеграцию с attention.
3. SAE-разложение ключей памяти (§4.6) — для интерпретируемости и более чистой
   похожести-по-смыслу.
4. Relative representations как zero-training fallback для переноса на другие модели
   (§4.7, §3.6).
5. Онлайн-MLP-память с explicit gate + active-neuron sparsity (§4.8) — отдельный,
   детально расписанный, но не начатый пайплайн; MVP-шаг 1 (чистый retrieval без обучения
   памяти) — самый дешёвый способ проверить, живёт ли вообще идея gate+injection.

## 10. Глоссарий

| Термин | Значение |
|---|---|
| **Dormant-токен** | Токен с нулевым текущим вниманием (например, «спящий» пароль в мусорном контексте), критичный для будущего вопроса, но невидимый для attention-массы. |
| **Surprise (удивление)** | Мера неожиданности входа для памяти/модели; в Titans — градиент ассоциативного лосса `∇ℓ(M(k),v)`; в наших экспериментах — также z-score L2-изменения hidden (EpiKV-стиль) или разница логпробов с/без контекста. |
| **η (eta) / η-голова** | «Как сильно писать» — адаптивный learning rate записи в память, зависящий от важности/новизны токена. |
| **γ (gamma) / γ-голова** | «Сколько забыть» — обучаемое забывание (decay) весов памяти. |
| **Alignment (фаза 1)** | Предобучение слотов памяти воспроизводить `M(h)≈h` на hidden Qwen — «память говорит на языке Qwen» до начала дистилляции. |
| **Bilevel-градиенты** | Градиенты, которые должны течь через ВНУТРЕННИЕ шаги обновления памяти (inner loop) к внешним параметрам (outer loop) — технически сложная часть, которая не заработала в наших 7 попытках и была обойдена заморозкой записи. |
| **MAC / MAG / MAL** | Три схемы интеграции памяти с attention в Titans: Memory as Context (soft-токены в K/V), Memory as Gate (явный гейт-блендинг после attention), Memory as Layer (последовательные слои). |
| **Write-gate** | Решение о полезности токена ДО записи в кэш/память (в отличие от эвикции — решения ПОСЛЕ записи). |
| **Персистентность между сессиями** | Главный проверяемый сценарий направления A: кэш Qwen выбрасывается между сессиями, веса памяти сохраняются на диск и переносят знание в новую сессию. |
| **target6 / mix** | 6-мерный вектор сдвига логпробов кандидатов — итоговый формат выхода рабочей памяти (§2.2), вместо векторной инъекции в hidden. |
