## Фаза 1 — Архитектурное решение: logit-shift vs input-injection (ГЕЙТ — решение пользователя)

**Что дочитать/доисследовать перед экспериментом:**
- `PLAN_MEMORY_V2.md` §1 (таблица сравнения двух вариантов).
- `RESULTS.md` — детали прошлого провала векторной инъекции (где именно подмешивали,
  какие нормы были).
- `ARCHITECTURE.md` — решение №3 (почему вообще ушли в логпроб-пространство).

**Эксперимент 1a (диагностический, 1 прогон, короткий):**
прототип input-injection на базе v5:
```
h_in[-1] += g · W_out(read_diff(q, work))   # W_out: 896→896 (временный, не 896→6)
h_out' = last_layer_forward(h_in с инъекцией)
loss = MSE(h_out', h_outB) + λ·CE(cand_logits(h_out'), секрет)
```
Сравнить с текущим logit-shift на ТОМ ЖЕ датасете: val_acc, val_mse, норма реальной
инъекции. Если val_acc сопоставим — input-injection стратегически предпочтителен
(открытый словарь, не 6 известных кандидатов); если нет — официально закрываем ветку
и приводим докстринг в соответствие с кодом.

**Выход:** таблица «logit-shift vs input-injection» с числами → **РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ**.
Дальнейшие фазы выполняются под выбранную архитектуру.
