# Трёхуровневая память: KV-кэш + внешняя база + retrieval, с MLP-маршрутизатором

Статус: отдельная идея (развитие скоринга), 2026-08-03.

## 1. Схема

```
УРОВЕНЬ 1 — KV-кэш (горячий, GPU): топ-скоринг токены (~10%)
      │  выгрузка (НЕ выбрасывание!)
      ▼
УРОВЕНЬ 2 — Внешняя база (векторная, диск/RAM): остальные токены + что не влезло в контекст
      │  retrieval, когда "не нашлось в кэше"
      ▼
      → найденные KV возвращаются во внимание (как обычные ключи)
```

MLP-скоринг = МАРШРУТИЗАТОР между ярусами, три роли:
1. что ОСТАВИТЬ в кэше (текущая работа);
2. что ВЫГРУЗИТЬ в базу (а не удалить) — решает по скору: высокий скор, но не влез → база;
3. что ИСКАТЬ в базе — формирует retrieval-запрос (удивление/аннотация как сигнал запроса).

Страховка: спящий пароль, не попавший в кэш, НЕ теряется — выгружается в базу,
при вопросе retrieval достаёт его. База страхует ошибки скоринга.

## 2. Кто "админит" у других (маршрутизация существует у всех)

| Система | Админ/маршрутизатор |
|---|---|
| RetrievalAttention | обученные адаптеры-предсказатели страниц (ANNS) |
| InfLLM | эвристика важности блоков |
| kv2state (tiered cache) | мульти-сигнальный скоринг: attention, recency, cross-head variance, distinctiveness |
| Memorizing Transformers | kNN-поиск без маршрутизации (просто retrieval над кэшем) |
| PQ-Cache / MagicPIG | MIPS/LSH retrieval без обучения |
| **Наш** | **обученный скоринг: attention + удивление + аннотация** (семантика!) |

У всех есть админ (обученный или эвристический). Наша особенность — сигналы:
удивление (спящие токены) и аннотация (семантическая важность).

## 3. Замедление инференса

- Уровень 1 (кэш): без изменений — скоринг бесплатен (одна MLP-прогонка).
- Уровень 2 (база): retrieval добавляет +10–100 мс на запрос (FAISS/ANNS, зависит от размера
  базы). Стратегия: retrieval ТОЛЬКО когда "не нашлось в кэше" (редко) — оверхед почти нулевой.
- На коротких контекстах база не нужна вообще (всё в кэше) — включается по порогу длины.

## 4. Как Titans решает "что запоминать" (наш референс)

Titans (код titans-pytorch/neural_memory.py):
- **Что запомнить**: surprise = пер-сэмпл градиент ассоциативной потери
  ||M(k)−v||² по весам памяти (`per_sample_grad_fn = vmap(grad(...))`).
  Неожиданный токен → большой градиент → сильная запись.
- **Как сильно**: adaptive lr η_t = σ(W_η x_t)·η_max — сеть учится скорости запоминания.
- **Что забыть**: decay γ_t = σ(W_γ x_t) — обучаемое забывание (`assoc_scan(1−γ, update)`).
- **Удержание во времени**: momentum S̄_t = η_t·S_t + θ_t·S̄_{t−1}.
- **Как тренируется**: end-to-end bilevel — внутренние шаги записи дифференцируемы,
  градиенты текут в W_η, W_γ, проекции и в модель (outer = задача, inner = запись).

Перенос в НАШ скоринг (не память-в-весах, а важность-в-кэше):
- η-голова  = "как сильно держать токен"  = наш скор;
- γ-голова  = "забывание" = decay скора по времени (старые токены слабее);
- surprise  = градиент-сигнал = наша голова удивления;
- bilevel   = контрафактика: удалил токен → ответ изменился → скор должен был быть выше.
  Это обучение "по конечной полезности", аналог TTT-обучения, но проще (без градиентов
  через внутренние шаги — только пересчёт ответа).

## 5. Перенос на другие модели (переходники vs домены)

Честный расклад:
- **Переходник размерности** (Linear(d_other → d_896) перед скорингом): технически работает,
  но hidden-распределения разных моделей не совпадают → качество падает. Только как
  стартовая точка + дообучение.
- **Обучение под домен/модель**: так делают все (KVzap: свои веса на каждую модель).
  Стоит 30–60 мин (автоматический датасет + быстрый тренинг). НЕ сильная навеска.
- **Инвариантные фичи** (частичный перенос): учить скоринг на нормализованных сигналах
  (z-score удивления, относительные ранги attention-массы, аннотации) — тогда часть
  знаний переносится, но точность требует лёгкого дообучения на новой модели.
- Итог: полный drop-in без переобучения невозможен (разные hidden-пространства);
  лёгкое дообучение на каждой модели — стандарт и дёшево.

## 6. Третья голова — на чём учится (уточнение)

- ОБУЧЕНИЕ: target = важность токена ИЗ АННОТАЦИИ (important=1, unimportant=0),
  вход = hidden states. Аннотации есть только в датасете.
- ИНФЕРЕНС: вход = только hidden states (как у других голов), выход = предсказанная
  семантическая важность. Аннотации НА ИНФЕРЕНСЕ НЕ НУЖНЫ — голова их не требует,
  она выучила ПРЕДСКАЗЫВАТЬ важность по hidden.
- Аналогия: как модель учится переводу на парах (текст, перевод) — на инференсе
  перевод не нужен, она уже умеет.

## 7. Порядок внедрения

1. Третья голова (annot) — 2–3 часа, готово всё для датасета.
2. η/γ-головы (Titans-перенос: сила держания + забывание) — 1 день.
3. Контрафактическое обучение (bilevel-аналог) — 1–2 дня.
4. Уровень 2: выгрузка в базу вместо выбрасывания + retrieval по порогу — 2–3 дня
   (FAISS, готовые референсы RetrievalAttention).
