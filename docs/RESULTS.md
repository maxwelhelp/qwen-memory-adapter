# Результаты: обученный MLP-скоринг для KV-эвикции (2026-08-03)

## Постановка
- Модель: Qwen2.5-0.5B-Instruct, eager, chat-формат.
- Задача (dormant): «Пароль: X7K9Q2» в середине мусорного контекста; эвикция решается
  ДО вопроса (пароль «спит»); вопрос добавляется после — его токены всегда видимы.
- Эвикция: additive 3D-маска (−inf для выброшенных ключей) на ВСЕХ слоях,
  внимание (softmax/QKV) НЕ меняется.
- Budget 10% top-K + sliding window 64; оценка: первый токен ответа = первый символ пароля.
- Скоринг: одна сеть (backbone 896→256), две головы:
  голова A = attention-масса (учитель), голова B = удивление z-score (EpiKV-дух);
  score = sa + β·ss; union top-K со страховочной attention-массой (top-K/3).

## Результаты (20 примеров)

| Режим | Ответ | Спящий пароль сохранён |
|---|---|---|
| dense | 20/20 (100%) | 20/20 (100%) |
| attn_mass (H2O-стиль) | 4/20 (20%) | 0/20 (0%) |
| ours β=0.0 (attention-голова + страховка) | 16/20 (80%) | 13/20 (65%) |
| ours β=0.5 | 16/20 (80%) | 13/20 (65%) |
| ours β=1.0 (удивление, без страховки) | 4/20 (20%) | 13/20 (65%) |

## Выводы
1. Dormant-проблема воспроизведена: attention-масса выбрасывает спящий пароль в 100%
   случаев (ответ = случайность 20%). Согласуется с Transactional Attention (2604.11288).
2. Обученный скоринг с удивлением сохраняет спящий пароль в 65% — удивление ловит то,
   что внимание не видит.
3. Union со страховкой вниманием обязателен: β=0/0.5 → 80% ответов (сохранены и пароль,
   и маркер «Пароль:»); β=1.0 без страховки → 20% (удивление выбрасывает маркеры).
4. Итог: обученный двухголовый скоринг + union бьёт H2O-стиль в 4 раза (80% vs 20%)
   при том же бюджете 10%.

## Шаг 1 персистентной памяти (2026-08-03): классификатор know/not-know

Постановка (titans_qwen.md, фиксы Дыры 1 и 3):
- Точка измерения: hidden последнего слоя на позиции t−1 ПЕРЕД значением факта
  («Столица Франции — |Париж» — модель предсказывает «Париж», не увидев его).
- Лейблы ЭМПИРИЧЕСКИЕ: zero-shot ответ Qwen на вопрос про факт (без контекста).
  Кандидаты: факты до 2022 (know) + события 2024-2025 (notknow); лейбл ставит
  сама модель, календарь нужен только для набора кандидатов.
- Вывод по пути: 0.5B знает только 18/69 «простых» фактов («столица России» →
  «Санкт-Петербург»!) — эмпирика честнее, чем предположения о срезе.

Результаты (dataset_knowledge.pt, 50 примеров: 18 know / 32 notknow, 5-fold CV):

| Метод | Accuracy | AUC |
|---|---|---|
| Классификатор (hidden+entropy+logprob) | 0.92 ± 0.04 | 0.974 |
| logprob-порог (эвристика) | 0.86 ± 0.10 | — |
| entropy-порог (эвристика) | 0.60 ± 0.11 | — |

Выводы:
1. Онлайн-сигнал новизны РАБОТАЕТ: один forward различает «знает из весов» vs «не знает».
2. Hidden-классификатор бьёт эвристики (особенно энтропию), стабильнее по фолдам.
3. logprob первого токена — дешёвая запасная фича (0.86).

Артефакты: gen_knowledge_dataset.py, dataset_knowledge.pt, train_knowledge_clf.py,
clf_knowledge.pt.

## Шаг 2 (2026-08-03): механика памяти на синтетике (smoke_memory_slots.py)

Проверялось: запись пар (key→value) градиентными шагами по чанкам + η/γ, чтение по ключу.
Слоты: 256 × (Linear или 2-слойный MLP 896→256→896), маршрутизация по route_keys
(пока случайные — обучаться будут на шаге 3).

| Проверка | Линейный слот (η=0.5, 1 шаг/пару) | Нелинейный (η=0.1, 16 итер.) |
|---|---|---|
| запись улучшает чтение | 0.336 → 0.189 (−44%) | 0.259 → 0.217 (−16%) |
| изоляция слотов | старые не пострадали | старые не пострадали |
| γ-стирание (η=0, γ=0.1) | 0.186 → 0.200 (забыла) | 0.215 → 0.230 (забыла) |
| перезапись факта (v2 на тот же ключ) | v2 вытесняет v1 | v2 вытесняет v1 |
| персистентность (save/load) | без потерь | без потерь |
| L_fast/L_slow | различие γ работает, НО: | slow копит шум |

Выводы:
1. Механика Titans-записи живая: шаг на пару/токен + γ-декей + η-сила + чанки.
2. top-k чтение с НЕОБУЧЕННОЙ маршрутизацией теряет (0.234 vs 0.189 жёсткого) —
   маршрутизацию/проекции учим на шаге 3 (дистилляция).
3. Урок для L_fast/L_slow: разделять по ПОРОГУ/ЧАСТОТЕ записи, не только по γ.
   L_slow пишет только при устойчиво высоком novelty (titans_qwen2.md), иначе шум
   отравляет долгую память.
4. Нелинейные слоты требуют итеративной записи (16+ шагов на чанк) — учесть в шаге 3.

Артефакты: smoke_memory_slots.py (SlotMemory: слотами, η/γ, чанками, read_slot/read).

## Шаги 3-4 (2026-08-03): дистилляция памяти + МЕЖСЕССИОННЫЙ ТЕСТ — РАБОТАЕТ

Постановка: 4 типа задач (Пароль/Код/Пин-код/Секрет: X в мусорном контексте, NOISE×1),
вопросы «Назови ... одним словом. Ответ:» (dense-контроли 20/20). Память пишет контекст
в сессии 1, сессия 2 — вопрос без контекста.

Что не работало (7 прогонов) и что починило:
1. Билевел-градиенты через запись НЕ доходят (клоны весов обрывают граф, mix ≈ 0) →
   ЗАМОРОЗКА слотов: запись = необучаемая механика (нормированные шаги самовосстановления
   на автономных клонах), чтение = обучаемое извлечение (W_route веса слотов, W_out, g).
2. Пространство памяти не связано с пространством Qwen → ФАЗА 1 ALIGNMENT: слоты учатся
   M(h) ≈ h на скрытых состояниях (память «говорит на языке Qwen»), затем заморозка.
3. Подмешивание вектора в hidden-пространство требует космической точности (Δ~150,
   norm() давил сигнал и градиенты) → выход памяти = 6 чисел = СДВИГ ЛОГПРОБОВ кандидатов:
   final_logits[кандидаты] = logits_noctx[кандидаты] + g·W_out(Σ w_i(work_i(q) − θ₀_i(q))).

Межсессионный тест (eval_cross_session.py, 40 примеров):

| Тип | Без памяти | С памятью | С контекстом |
|---|---|---|---|
| Пароль | 1/10 | 10/10 | 10/10 |
| Код | 2/10 | 4/10 | 10/10 |
| Пин-код | 0/10 | 10/10 | 10/10 |
| Секрет | 2/10 | 10/10 | 10/10 |
| ИТОГО | 5/40 (12%) | 34/40 (85%) | 40/40 |

Выводы:
1. ПЕРСИСТЕНТНАЯ ПАМЯТЬ РАБОТАЕТ: Qwen без контекста отвечает правильно в 85% случаев
   (шанс 12%) — знание хранится в весах памяти между сессиями, кэш не нужен.
2. «Код»-тип отстаёт (4/10) — байас Z6F3H8; вероятно, тип недообучен (равновесие W_route
   под другие типы) — фикс: больше примеров на тип / per-type батчи.
3. Ключевые уроки: (а) запись и чтение — РАЗНЫЕ механизмы (запись необучаемая механика,
   чтение обучаемое извлечение); (б) alignment-предобучение пространства обязательно;
   (в) выход в пространство логпробов кандидатов вместо hidden-вектора.

Артефакты: gen_yattn.py, dataset_yattn.pt (400 примеров), train_memory_distill.py
(alignment → заморозка → дистилляция), memory_distill.pt, eval_cross_session.py.

## MLP-слоты (3.1, 2026-08-03): нелинейная память работает

- Слот = MemoryMLP-стиль (Linear 896→H→896, GELU, без bias, xavier_uniform).
- НАЙДЕНО: residual-обёртка (MLP(x)+x, как в Titans) УБИВАЕТ нашу схему —
  mix = разность откликов (запись − θ₀), а residual сводит запись к нулю
  (||MLP(h)||² → 0) → mix ≈ 0, acc = шанс. Для нас residual НЕ нужен.
- Быстрый прогон (120 примеров, 20 эпох, H=256, ITERS=2):
  val_acc 0.68 | межсессионный 23/40 (57.5%) vs шанс 5/40 (12.5%),
  линейные слоты: 34/40 (85%).
- Вывод: нелинейная память пишет/извлекает, но быстрый прогон недоучен
  (байасы R9L2X4/M4N8Z1). Нужен полномасштабный прогон (320/50/H=896).
- Уточнение после правок (векторизация + живой alignment + LR=3e-3):
  val_acc 0.70, межсессионный 23/40 (57.5%) — MLP-память работает стабильно,
  но слабее линейной (34/40). LR=1e-3 был слишком медленным (val_acc застревал
  на 0.25); векторизация чтения (einsum-батч) численно эквивалентна
  functional_call (diff 7e-6); alignment должен строиться из ЖИВЫХ θ₀
  (detach-кэш обрывал градиенты — alignment молча не учился).
- Следующее: 3.2 — η-голова (что писать): учитель = позиции секрета в контексте.

## 3.2 (2026-08-04): η-голова — «что записывать»

- Учитель: mask_secret (позиции секрета в контексте, 1/0) — в gen_yattn.
- η_t = η_min + (η_max−η_min)·σ(W_eta(h_t)), η_min=0.1, η_max=1.0;
  шаг записи токена взвешивается η_t («novelty гейтит θ_t»).
- Результат: η выучилась мгновенно (секрет≈1.00, мусор≈0.10).
- Межсессионный тест MLP+η: 24/40 (60%) vs 23/40 без η vs 34/40 линейные.
- Вывод: η-голова работает, но прирост мал — запись не была узким местом.
  MLP-память стабильно уступает линейной в текущей схеме (разность откликов
  у нелинейных слотов слабее). Дальше: 3.3 (полный bilevel TTT-стиля) или
  тюнинг MLP (ITERS/H/эпохи).
